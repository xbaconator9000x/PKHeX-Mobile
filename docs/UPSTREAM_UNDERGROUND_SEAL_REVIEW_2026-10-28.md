## P0 implementation handoff

**Highest risk:** MAUI Gen4 pouch saves compact entries without clearing tails; malformed IDs can crash label lookup; static pages retain a captured save reference; navigation itself commits multiple live writes. For BDSP, Core's whole-table serialization can normalize untouched 32-bit flags, and Forge's count-only mutation invokes that path. These are **source-level hazards requiring isolated reproduction**, not claims of actual user-save corruption.

## Architecture, format and licensing disposition

Use the **pinned official Core** for version-specific parsing, but copy all read-only data to bounded immutable structures before exposing it to Android. For Gen4, preserve each of the 40/40/40/80 raw pouch bytes and all 13 u32 scores; do not derive write authorization from localized item labels. For BDSP, represent each of 999 underground records, 200 sticker records and 99×20 capsule affixes separately, preserving raw flag words and signed coordinates. Future writes must stage a complete candidate, authenticate the exact save layout, verify a strict field-level allowlist, back up original bytes, independently reopen using desktop-matched fixtures, and prove rollback on provider failure. **Unsupported hacks must remain read-only even when a user accepts a warning.**

PKHeX.Core declares `GPL-3.0-or-later` ([C:PKHeX.Core.csproj:9-18](https://github.com/kwsch/PKHeX/blob/7e26bc53215e4f7bc0041ca375f1042539cb81b3/PKHeX.Core/PKHeX.Core.csproj#L9-L18)); PKForge's pinned repository carries GPLv3 and MAUI's `LICENSE.txt` contains GPLv3, but neither proves independent rights to packaged game artwork, sprites, fonts or datasets. MAUI explicitly packages numerous image/font paths ([M:PKHeX.MAUI.csproj:90-115](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/PKHeX.MAUI.csproj#L90-L115)). No code or assets were imported in this audit.
