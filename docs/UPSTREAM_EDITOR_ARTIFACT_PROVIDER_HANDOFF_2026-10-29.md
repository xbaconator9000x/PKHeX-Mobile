# Port consolidation: the compiled editor is not the downloadable app — 2026-10-29

**Decision / implementer handoff:** Stop extending the source inventory. **Make the already-compiling, read-only PKForge MAUI editor into a reproducible, identifiable Android test artifact** before adding more editor tabs. Retain official PKHeX.Core 26.10.18, the independent domain safety boundary and the preview-only write denials. **Do not ship an APK, enable Save As, or claim desktop parity merely because compilation passed.** This document is a source/CI audit, not a device or export test.

## P0 integration handoff: two different APK pipelines, neither a certified editor release

The [official-Core probe workflow](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/2c759621c5728c03c050bffbb7efd5ab7598db83/.github/workflows/pkforge-official-core-probe.yml) checks out PKForge **under `/tmp/pkforge`**, applies temporary source transforms, and runs `dotnet build ...PKForge.App.csproj -f net10.0-android -c Debug -p:AndroidPackageFormat=apk`. It has **no `actions/upload-artifact` step** and no published integration project or reproducible APK handoff. The CI success proves this temporary adaptation compiles, not that a user can install and test the adapted editor.

By contrast, the [native Android workflow](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/2c759621c5728c03c050bffbb7efd5ab7598db83/.github/workflows/android-build.yml) **does** upload `pkhexmobile-readonly-debug-apk`, but builds **`src/PKHeXMobile.Android`**, the separate read-only viewer, not the adapted PKForge MAUI editor. A green Foundation run also does not execute the PKForge probe on documentation-only changes: that probe is path-filtered to implementation changes or manual dispatch.

**Consequence:** a downloadable native APK must never be described as the integrated PKForge Pokémon editor. The shortest critical path is a deterministic packaging/launch smoke for the adapted MAUI app, with provenance and licensing review; keep the native viewer as a separate explicitly labelled fallback. The [pinned PKForge project](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/PKForge.App.csproj) uses `org.pkforge.app.debug` in Debug, and bundles numerous upstream artwork/media assets. Rebrand/package and asset selection need a reviewed, reproducible manifest; do not silently redistribute all of them.

## P0/P1 remaining trust boundaries

1. **Provider identity is not authenticated.** [ProviderBoundRetailNicknameEditor](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/2c759621c5728c03c050bffbb7efd5ab7598db83/src/PKHeXMobile.PortConsolidation/ProviderBoundRetailNicknameEditor.cs) verifies immutable provider bytes before and after preview, plus an opaque document ID and session generation, but cannot detect same-byte replacement of the document/provider. [SaveDocumentSession](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/2c759621c5728c03c050bffbb7efd5ab7598db83/src/PKHeXMobile.Domain/SaveDocumentSession.cs) already has a `DocumentReadHandle` with optional `DocumentSourceIdentity`; adapt that seam instead of inventing another reader. Identity confirmation alone still does **not** authenticate retail game layout or authorize writing.
2. **Preview overlay lifecycle is not covered by synthetic provider tests.** [MAUI preview injection](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/2c759621c5728c03c050bffbb7efd5ab7598db83/scripts/pkforge_detached_preview_ui.py) checks request/selection before `await PadMenu.ShowAsync` but does not cancel/dismiss a displayed overlay on later navigation, close or selection change. This is an **unreproduced source-level UI race**, not a demonstrated stale display. Test with controlled pending overlay and Android Back.
3. **Retail versus same-size ROM-hack save discrimination remains unproven.** [DetachedRetailNicknameEditor](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/2c759621c5728c03c050bffbb7efd5ab7598db83/src/PKHeXMobile.PortConsolidation/DetachedRetailNicknameEditor.cs) uses official Core validation and PKForge layout/scope checks, but its synthetic Gen6 fixture is not a representative retail/hack differential oracle. No export promotion on these results.
4. **Safe Save As is not implemented or certified.** The [pinned PKForge SAF writer](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs) opens the original URI with `rwt`; reject it for publication. Preserve original write denials until distinct destination, alias detection, staged candidate readback, interruption and independently reopened output pass.
5. **Rights and dependency packaging must be audited before distributing the MAUI artifact.** [PKForge app csproj](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/PKForge.App.csproj) includes PKHeX sprites, Showdown icons, Luminescent icons, GameArt and fonts. [PKForge LICENSE](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/LICENSE) and [PKHeX MAUI LICENSE](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/LICENSE.txt) contain GPLv3; [official Core csproj](https://github.com/kwsch/PKHeX/blob/bfe89c74a3f5265805e364b79bc04ad38ebbc5ea/PKHeX.Core/PKHeX.Core.csproj) declares GPL-3.0-or-later. That does not establish rights to every asset. [MAUI project](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/PKHeX.MAUI.csproj) also depends on older Core 26.7.7 and prebuilt AutoMod/Injection DLLs; reject blind binary transplant.

## Next implementation batch — narrow and measurable

1. **Deliver a reproducible adapted-editor test artifact** from the already passing temporary build, with source SHA, transform SHA list, Core package, SDK, APK hash and distinct package ID. Initially keep it **internal/test-only** until every included asset and dependency is cleared. Do not confuse it with the native viewer artifact. Preserve all original-document writer denials.
2. **Run the APK on Android** with a synthetic, non-sensitive fixture: launch, pick, inspect party/box, nickname preview, cancel, Back, reopen, rotation/process recreation and denied-write spy. Record Android API level/provider and screenshots/logs without private save bytes.
3. **Bind identity-bearing provider read handles** and execute same-byte replacement/changed identity negative tests. Permit preview with an explicit unverified-source status if identity is unavailable, but never promote that session to Save As.
4. **Real retail/hack differential** and desktop oracle, then **distinct-destination Save As** with independent readback and original fingerprint check. Add desktop editor tabs only after this transaction passes.
