## Source-backed observations and implementer tickets

### P0/P1: SAF read-only trust and lifecycle

**D-IO-01 — least-privilege picker is a positive boundary, not a certified provider implementation (P1).** [MainActivity.cs L65–78](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/MainActivity.cs#L65-L78) uses `ACTION_OPEN_DOCUMENT`, `CATEGORY_OPENABLE`, `*/*`, and only `GrantReadUriPermission`. The [manifest](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/AndroidManifest.xml) declares no storage/network permissions, disables app backup and cleartext traffic. No output stream, file-path conversion, or write request is present in the inspected Activity. Contrast [Forge's picker L14–32](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs#L14-L32), which requests read **and write** plus persistable permission for its editing flow, and [MAUI's manifest](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/Platforms/Android/AndroidManifest.xml), which declares `MANAGE_EXTERNAL_STORAGE`. **Keep read-only least privilege; test actual grants from provider results before extending permissions.**

**D-IO-02 — the second open verifies bytes, not independently reported provider revision (P1).** [SaveDocumentSession.cs](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Domain/SaveDocumentSession.cs) hashes independently opened streams and rejects changed `DocumentSourceIdentity` values; [MainActivity.cs L101–113](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/MainActivity.cs#L101-L113) constructs the identity from `DocumentsContract.GetDocumentId(uri)` and the URI authority **for the same selected URI** on both opens. That is an opaque URI-derived identity hint, not a fresh provider generation/etag or proof of no same-byte replacement behind the URI. It is correctly labeled non-authoritative in the UI. **Test same-URI replacement, URI remap, content mutation, revoked grant, short streams and non-seekable streams. Never upgrade the hint to write authorization.**

**D-IO-03 — read-only session avoids source mutation but lacks device evidence (P1).** [ReadOnlyDocumentService.cs](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.ReadOnly/ReadOnlyDocumentService.cs) opens, parses and reopens even on parser refusal. [SaveInputSnapshot.cs](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Domain/SaveInputSnapshot.cs) limits each read to 32 MiB, uses private byte copies and SHA-256. [ReadOnlySaveInspector.cs](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.ReadOnly/ReadOnlySaveInspector.cs) only publishes a projection after Core recognizes valid checksums, applies provisional layout limits and negative-only risk checks. It cannot prove a retail save, especially for a hack with retail-shaped headers. **A read-only display must explicitly say provisional, as the Activity does.**

**D-IO-04 — transient URI grants are intentional; persisted access is not available (P1).** [MainActivity.cs](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/MainActivity.cs) never calls `TakePersistableUriPermission` and stores no selected URI for later sessions. That reduces retained access but requires a new picker selection after process death; do not advertise a persistent recent-file list. Forge [persists grants in AndroidSafFileAccess.cs](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs) and [its picker](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs), a different capability requiring revocation handling. **Test rotation/process death and permission expiry with no stale access claims.**

**D-LIFE-01 — Activity recreation/cancellation race needs instrumentation (P1).** [MainActivity.cs L80–157](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/MainActivity.cs#L80-L157) handles results in `async void`, executes provider I/O/Core parsing via `Task.Run`, disables/re-enables a button and cancels a lifetime token in `OnDestroy`. This is sensible for a prototype, but no source-visible state restoration, persisted picker state, or instrumentation test proves that an old result cannot surface after rotation, rapid Home/Back, process death or Activity replacement. **Use an explicit request/session generation, lifecycle-safe result API and instrumented cancellation tests before release.** This is a test requirement, **not** an observed crash.

**D-LIFE-02 — exception reporting currently hides diagnosis (P2).** The [catch block L136–146](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/MainActivity.cs#L136-L146) deliberately shows a generic message for all non-cancellation exceptions. This avoids leaking private document paths, but also provides no source-visible error classification for malformed input versus provider permission, timeout, I/O or parse failure. **Add privacy-safe typed diagnostics and opt-in redacted logs; never upload raw saves, URIs, trainer names or fingerprints by default.**

**D-LIFE-03 — no explicit user cancellation/progress path for long providers (P2).** The Activity's [single `Task.Run` invocation](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/MainActivity.cs#L99-L115) only uses its destruction token; while the operation is running the Open button is disabled. A slow cloud provider may make the screen appear stuck. **Add an explicit cancel control, bounded provider timeout policy, and progress/phase status.** Verify cancellation propagates without leaving an open stream.

### P1: CI and dependency provenance

**D-CI-01 — Android workflow misses shared-code changes (P1, concrete).** [android-build.yml L4–12](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/.github/workflows/android-build.yml#L4-L12) triggers only for `src/PKHeXMobile.Android/**` and its own YAML. Yet [Android.csproj](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/PKHeXMobile.Android.csproj) references ReadOnly, which references Domain and the pinned Core package. A change only in `src/PKHeXMobile.ReadOnly/**`, `src/PKHeXMobile.Domain/**`, or package/build properties **does not automatically schedule the Android compile workflow**; the foundation workflow runs managed tests but does not build Android. **Expand path triggers to every transitive Android build input, or add a cheap always-on build-input-diff guard with manual workload build.** Reproduce with a disposable PR changing only ReadOnly.

**D-CI-02 — SDK/workload/actions are not fully reproducible (P1).** [android-build.yml L20–38](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/.github/workflows/android-build.yml#L20-L38) uses floating `10.0.x`, `dotnet workload install android --skip-manifest-update`, and action major tags. The inspected repository tree has no `global.json`, NuGet lockfile, or checked-in Android workload manifest baseline. The NuGet **version** is exact, but no package-byte hash/locked dependency closure or generated APK hash manifest is checked in. **Record SDK feature band, Android workload/SDK, Java, resolved NuGet hashes, action revisions and APK SHA-256; validate reproducible restore/build independently.** Do not call a green build reproducible.

**D-CI-03 — compile-only artifact cannot certify install/launch (P1).** [android-build.yml](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/.github/workflows/android-build.yml) builds Debug and uploads a seven-day APK; there is no emulator instrumentation, picker UI automation, provider fault injection, or installed-package smoke test in that job. **Add at least one emulator install/launch smoke gate plus private device/provider runs**, and report them separately from compile CI.

**D-CI-04 — README and Core-pin descriptions lag implementation (P2).** [README.md](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/README.md) and [CORE_PIN.md](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.ReadOnly/CORE_PIN.md) still state no Android UI/APK, although the build has produced a debug APK. [UPSTREAM_REVIEW.md](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/docs/UPSTREAM_REVIEW.md) also contains an older pre-Android status line. This is a **documentation accuracy ticket for the implementation owner**: preserve the first README line exactly `# This is a test.`, distinguish experimental compiled APK from verified install/device support, and update stale status text. Audit-owned index may link this checkpoint without touching implementation-owned files.

### P1/P2: mobile presentation and parity

**D-UI-01 — current presentation is a single long text projection, not a box browser (P1).** [MainActivity.cs L23–62 and L158–196](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/MainActivity.cs#L23-L196) builds one vertical `ScrollView` with heading/button/status and a `TextView` containing every reported box and occupied slot. There is no box selector, per-slot inspector, item/move view, pagination, accessible slot actions, or edit controls in this Activity. The [official desktop Main](https://github.com/kwsch/PKHeX/blob/7e26bc53215e4f7bc0041ca375f1042539cb81b3/PKHeX.WinForms/MainWindow/Main.cs) uses a separate save editor and Pokémon tabs; [Forge's BoxBrowserPage](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/BoxBrowserPage.cs) implements a box grid and side panel, but explicitly targets a **landscape-only AYN Thor-style layout**; [MAUI BoxTab](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/boxtab/BoxTab.xaml.cs) builds a six-column collection with slot interactions. **Design a virtualized, accessible portrait-first phone UI with tablet/landscape adaptation; do not copy game artwork or wholesale landscape UI.**

**D-UI-02 — data semantics are intentionally narrow (P1).** [ReadOnlySaveInspector.cs](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.ReadOnly/ReadOnlySaveInspector.cs) projects species numeric ID, nickname, level, egg/shiny, trainer IDs, party and occupied boxes. It does **not** project moves, held items, ability, nature, met data, stats, legality analysis, ribbons, memories, Mystery Gift, events, bank, batch or trainer editing. This is a source-backed inventory of **this reader only**, not an assessment that the Core lacks these capabilities. See [28-row capability crosswalk](PARITY_MATRIX_2026-10-27.md). **Require a per-field source/API/fixture crosswalk before exposing each field.**

**D-UI-03 — accessibility and responsiveness are unverified (P2).** [MainActivity.cs](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/MainActivity.cs) uses fixed text sizes and a single scrollable text blob; there is no source-visible UI test for TalkBack order, dynamic font scaling, keyboard navigation, large boxes, screen rotation or narrow displays. Forge's [BoxBrowserPage](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/BoxBrowserPage.cs) offers a useful input model but is optimized for landscape/controller, while MAUI's [BoxTab](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/boxtab/BoxTab.xaml.cs) uses touch gestures and image assets whose redistribution rights are not established for this project. **Measure, do not assume, accessibility and memory/performance.**

**D-UI-04 — platform baseline is deliberately narrower than the candidate MAUI app (P2).** [Android.csproj](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/7ad00f492982b2ee4d3b8cb39034f8a0a5c442a6/src/PKHeXMobile.Android/PKHeXMobile.Android.csproj) sets minimum Android API 26, whereas [MAUI.csproj](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/PKHeX.MAUI.csproj) declares Android minimum 24 and target `net10.0-android36.0`. These are declared settings, **not evidence of actual OS compatibility**. **Test API 26, 29, 33, 35/36 with local and cloud providers before claiming support.**

### Architecture and licensing disposition

Keep the **official pinned PKHeX.Core + independent native Android presentation + path-free read-only service** as the provisional implementation. A compile-successful native Activity is meaningful progress but **does not close Milestone 0's architecture decision**: no candidate has passed an independently reproduced, like-for-like mobile build/device test, and no per-editor runtime parity has been demonstrated. Forge's landscape-only SkiaSharp box page and MAUI's XAML collection view are **design references**, not licensed/verified drop-ins.

[Official Core project](https://github.com/kwsch/PKHeX/blob/7e26bc53215e4f7bc0041ca375f1042539cb81b3/PKHeX.Core/PKHeX.Core.csproj) declares `GPL-3.0-or-later`; our repository remains GPLv3. [Forge app project](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/PKForge.App.csproj) includes multiple third-party artwork/font/sprite sources; [MAUI project](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/PKHeX.MAUI.csproj) bundles artwork and prebuilt AutoMod/Injection DLLs. **Do not import any third-party code, sprite, font or binary from either app without source attribution, license and corresponding-source verification.** The current native prototype uses text instead of imported game imagery. No external candidate source or media was copied in this audit.
