## Finding A — P0 evidence integrity: DocumentsUI foreground does not prove ACTION_OPEN_DOCUMENT

[PR #118's exact `scripts/pkforge_emulator_picker_cancel.py`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/98e42d1119900f0f1a1e74c8916c001c9696a2b8/scripts/pkforge_emulator_picker_cancel.py) `is_picker()` checks only whether `topResumedActivity` or `mResumedActivity` contains `com.google.android.documentsui/` or `com.android.documentsui/`. `open_picker()` sends gamepad B and X, or taps a visible `File`/onboarding label, then accepts any foreground DocumentsUI Activity. **That does not distinguish `Intent.ActionOpenDocument` from `ActionOpenDocumentTree` or another DocumentsUI launch.** The upstream [pinned single-save picker](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs#L14-L32) explicitly constructs `Intent.ActionOpenDocument`, while its app has other folder-selection routes. The [existing unit test](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/98e42d1119900f0f1a1e74c8916c001c9696a2b8/tests/test_pkforge_emulator_picker_cancel.py) asserts only a DocumentsUI package and synthetic B/X event ordering; it never verifies the actual launched intent action.

**Impact:** the smoke could pass after opening and cancelling the wrong system picker. This is a *test false-positive*, not a demonstrated write or runtime defect. **Smallest safe change:** retain the current PKForge UI route, but capture a bounded Android ActivityTaskManager launch record or instrumentation event for this specific transition; require `android.intent.action.OPEN_DOCUMENT` with `CATEGORY_OPENABLE` and a read-only grant request, and explicitly reject `OPEN_DOCUMENT_TREE`. Validate the event belongs to the observed launch rather than a stale earlier intent. A foreground DocumentsUI check remains necessary but is insufficient.

## Finding B — P1 privacy/test hygiene: full accessibility XML persists in shared /sdcard

The same [`ui_nodes()`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/98e42d1119900f0f1a1e74c8916c001c9696a2b8/scripts/pkforge_emulator_picker_cancel.py) writes the entire `uiautomator dump` to **`/sdcard/pkforge-ci-window.xml`**, reads it back, and returns or throws without deleting the file. Accessibility XML contains **all visible node text and content descriptions**, not merely the allowlisted onboarding labels printed by the script. The current CI uses an empty emulator with no save selected, so this is **not evidence of exposed user data**. But reusing this harness on a device/provider with sensitive filenames could leave a persistent XML artifact on external shared storage even when stdout remains sanitized.

**Smallest safe change:** prefer a validated in-memory `uiautomator` output path if the runner image supports it. Otherwise use a unique shell-private temporary path with a `finally` cleanup covering successful parse, malformed XML, retry exhaustion and ADB exceptions; ensure no external shared-storage copy survives. Never print the raw XML or document names to CI logs. Keep a fail-closed check for leftover files.
