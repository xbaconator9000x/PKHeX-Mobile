## Two precise gaps in the current emulator evidence

**EAB-01 — attested APK versus installed APK is not cryptographically bound (P0 evidence gate).** [PR #83 launch script](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/29c85858ca941e8c92968e0f38c971f4aa34e081/scripts/pkforge_emulator_launch_smoke.sh) selects the first `*-Signed.apk` found by `find ... -print -quit`, otherwise the first `*.apk`. The [attestation script on main](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/ef9b9e4fd2a0e2af907bd90d917162180c15c2c6/scripts/pkforge_artifact_attestation.py) hashes **all** discovered APKs and records each SHA-256 and package identity. The launch script neither chooses an exact attested filename/hash nor verifies installed package bytes correspond to that record. `pm path` confirms an installed package with the expected ID, not the identity of the artifact exercised. This is a reproducibility/verification gap, **not** evidence the tested APK was malicious or wrong.

**EAB-02 — process survival is narrower than interactive editor launch (P1).** The same script calls `adb shell monkey -p org.pkforge.app.debug 1`, waits 12 seconds, and asserts only `adb shell pidof`. A running process does not prove a resumed interactive Activity, visible box browser, successful MAUI rendering, SAF picker cancellation or privacy boundaries. The existing `tests/test_pkforge_emulator_launch_smoke.py` checks shell syntax and string presence, not those runtime conditions. Treat [CI 40824680904](https://github.com/xbaconator9000x/PKHeX-Mobile/actions/runs/40824680904) as **one emulator cold-install/process-survival test executed**, not UI/provider/device certification.

**EAB-03 — QR image buffer lifetime merits one narrow lifecycle test (P1, unproven risk).** Main's [`pkforge_residual_cache_refusal.py`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/ef9b9e4fd2a0e2af907bd90d917162180c15c2c6/scripts/pkforge_residual_cache_refusal.py) constructs `ImageSource.FromStream(() => new MemoryStream(png, writable: false))`, while the overlay close handler calls `Array.Clear(png)`. MAUI can request the stream asynchronously; the captured array is mutable and shared across those requests. This is **not** a reproduced blank/invalid QR, and it does not reopen binary .pk export. Inject a delayed stream factory and close/rotate rapidly; verify image decoding and no post-close retention before claiming RSC-07 complete. Do not replace the already-passing source-level QR containment tests.
