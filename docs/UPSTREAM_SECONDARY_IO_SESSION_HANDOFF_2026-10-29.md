# Secondary Android I/O and session activation: consolidation handoff (2026-10-29)

**Decision:** Keep the now-compiling PKForge Android MAUI shell and official PKHeX.Core, but close **two independent trust boundaries** before presenting the temporary adaptation as an end-to-end read-only editor: (1) a second, still-writable Android SAF *folder* stack, and (2) provider-bound source/session activation and preview provenance. Do not reimplement the editor. This is a source-level audit and executable test specification, **not** an observed device exploit or certified save export.

## What implementation has already fixed: do not reopen

PR #52 blocked PKForge's original-save writer at both `ISafeSaveWriter` and `ISaveFileAccess`, removed single-save write grants and guarded known BoxBrowserViewModel live-mutation paths. PR #54 adapted the Android single-save reader to `SaveInputSnapshot.ReadAsync` (32 MiB cap) and a two-open byte comparison. [The adaptation workflow](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/a9d18b417fff3d24e1e7823b54d7709e34b495c7/.github/workflows/pkforge-official-core-probe.yml) still builds a temporary PKForge app; it is not a device-certified product.

## P0-A: a separate SAF folder writer remains outside both containment barriers

The pinned [MauiProgram registrations](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/MauiProgram.cs) register `IFolderPicker, AndroidFolderPicker` and `IFolderFileAccess, AndroidFolderFileAccess` independently of `ISafeSaveWriter` and `ISaveFileAccess`. [Our containment transform](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/a9d18b417fff3d24e1e7823b54d7709e34b495c7/scripts/pkforge_readonly_containment.py) replaces **only** the latter two registrations.

The pinned [AndroidFolderPicker](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidFolderPicker.cs) requests `GrantWriteUriPermission` for `ACTION_OPEN_DOCUMENT_TREE`. [AndroidFolderFileAccess.WriteFileAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidFolderFileAccess.cs) finds an existing same-name child or creates one and opens it with `OpenOutputStream(target, "wt")`. It also reads folder files with unbounded `CopyToAsync`, unlike the newly hardened single-save reader. These are *independent* routes; the single-save writer spy cannot observe them.

The paths are reachable in existing workflows: [BankArchive.ExportAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/BankArchive.cs) calls `IFolderFileAccess.WriteFileAsync` for entries and manifest, and [PksmTransferFlow.ExportAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/PksmTransferFlow.cs) writes `.bnk` and `.json` files. This does **not** establish that an original Pokémon save is automatically overwritten; it establishes that a supposedly preview-only app can request a write grant and overwrite an existing **folder child** if an export path is invoked. A chosen folder could contain important files. Treat these as non-save export surfaces needing their own policy, not as safe Save As.

**Fast fix:** In the temporary read-only adaptation, register an `IFolderFileAccess` read-only wrapper that denies `WriteFileAsync` and caps `ReadFileAsync`; remove write flags from `IFolderPicker`, or disable the entire bank/folder export feature until independently verified. Reuse existing `SaveInputSnapshot` for bounded reads, rather than introducing a new parser. Preserve import-only read functionality where tests establish it. A later explicit export to a distinct user-chosen destination needs its own write contract and overwrite confirmation.

## P0-B: source verification is not bound to the mutable session or preview

[PKForge SaveSessionService.OpenAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SaveSessionService.cs) awaits `access.ReadAsync`, parses, calls `engineSession.MakeActive()`, disposes `CurrentSession`, and assigns `Current`. It has no monotonic request generation, per-document identity binding or cancellation check **after** engine parse / before activation. Two overlapping opens can therefore complete out of order; this is a code-path inference requiring a deterministic interleaving test, not a reproduced UI failure. [SavePickerViewModel](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/ViewModels/SavePickerViewModel.cs) and HomePage can invoke session open through distinct routes.

Our [two-open ReadOnlySaveFileAccess adapter](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/a9d18b417fff3d24e1e7823b54d7709e34b495c7/scripts/pkforge_source_read_hardening.py) compares *bytes* for the same URI string, but does not bind an opaque `DocumentSourceIdentity` to a persistent session object. Our already-implemented [SaveDocumentSession](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/a9d18b417fff3d24e1e7823b54d7709e34b495c7/src/PKHeXMobile.Domain/SaveDocumentSession.cs) provides original snapshot, identity-aware independent verification and revocation of stale confirmation. **Reuse that domain type as the provider-bound input boundary**, then hand its original bytes into the existing PKForge engine. Identity is a hint and does not certify retail layout.

The [MAUI detached preview injector](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/a9d18b417fff3d24e1e7823b54d7709e34b495c7/scripts/pkforge_detached_preview_ui.py) still calls `SaveInputSnapshot.FromBytes(session.Serialize().Span)`. That is a **mutable session serialization**, not the immutable provider snapshot; it also captures box/slot/nickname before awaiting the overlay without a generation/fingerprint recheck. [DetachedRetailNicknameEditor](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/a9d18b417fff3d24e1e7823b54d7709e34b495c7/src/PKHeXMobile.PortConsolidation/DetachedRetailNicknameEditor.cs) already accepts a detached `SaveInputSnapshot` and has `RequireMatchingSource`. Keep this implementation; replace the preview's source and stale-result handoff, not its editing logic.

**Fast fix:** capture one immutable `ProviderSession` record (opaque URI, optional source identity, source fingerprint, original snapshot, selected game/profile, monotonically increasing generation) after bounded two-open verification. Every open/close/revert increments generation; only the latest generation may activate or display a preview. Parse and edit detached bytes. Re-check generation, fingerprint, identity and source before any eventual publication; never derive an export baseline from `session.Serialize()`. Keep save writing disabled pending authenticated retail layout and independent staged Save As.

## P1-C: multi-file picker remains a separate lifecycle path

Pinned [AndroidDocumentPicker.PickManyAsync / HandleMultiResult](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs) has no cancellation registration, retains `_pendingMany` until a result, accepts each returned URI after catching *all* persistence exceptions, and does not explicitly validate the returned read grant. The [PR #55 picker transform](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/a9d18b417fff3d24e1e7823b54d7709e34b495c7/scripts/pkforge_picker_lifecycle.py) changes only `PickSaveAsync` / its single-result branch. The multi-file path is used by [PksmTransferFlow.ImportAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/PksmTransferFlow.cs); reads there pass through the hardened `ISaveFileAccess`, but the picker lifecycle and batch count still need separate tests. Do not claim this path fixed by PR #55.

## Adopt/adapt/reject matrix for the remaining critical path

| Surface | Decision | Reuse and missing acceptance |
| --- | --- | --- |
| Working Android UI, party/box, editor | **ADAPT PKForge** | Official-Core Android compile already passes; wire provider-bound preview and cancel; phone/tablet/device launch unverified. |
| Retail save parsing | **ADOPT official Core, ADAPT PKForge retail route** | Positive authenticated retail fixture, same-version desktop round-trip and valid-looking hack lookalikes remain missing. |
| Pokémon nickname editor | **ADOPT detached PKForge edit adapter** | Synthetic serialization/reopen works; source provenance, session generation and real UI interaction missing. |
| Legality | **ADAPT PKForge grouping on official Core** | Desktop-matched reports and game-context gating missing; no independent fork legality oracle. |
| Single-save Android picker/read | **ADAPT current hardened PKForge** | PRs #52–#55 pass compile/synthetic gates; identity binding and device provider races missing. |
| Folder picker/file access | **REJECT writes in preview-only; ADAPT reads** | Independent writer + writable folder grant remain; guard or disable bank export. |
| Multi-file picker/import | **ADAPT selectively** | Cancellation, read grants, batch bounds, stale results and revocation need tests. |
| Save writer/backup | **REJECT PKForge original-URI `rwt` writer** | Reuse domain preflight; only independently verified, distinct-destination Save As may later publish. |
| PKHeX MAUI game editors | **ADAPT individual screens later** | GPLv3 source available, but package `26.7.7` and static mutable state are not current-Core integration proof. |
| Tests/builds/assets | **ADOPT source-pinned compile + synthetic harness; ADAPT device tests** | No real provider, physical device, original-safe export, signed release or full desktop parity. Preserve source notices; do not import upstream art without separate rights audit. |

## One cohesive implementation batch (not another broad audit)

1. Deny `IFolderFileAccess.WriteFileAsync` and folder write grants in the **temporary** read-only app; run folder writer-spy, read cap, archive/export button and permission tests.
2. Bind PKForge session activation and nickname preview to our existing immutable `SaveDocumentSession`, add generation-based latest-request-wins and deterministic overlapping-open/close/revert tests.
3. Harden the separate multi-picker only if import remains enabled; otherwise disable it for the first preview release. Run Android provider instrumentation before device claims.
4. Only then implement detached, independently verified Save As to a **distinct** URI, after retail-positive fixtures and desktop parity gates. Never reuse `AndroidFolderFileAccess.WriteFileAsync` as a substitute for safe save export.

See [companion executable gates](PARITY_SECONDARY_IO_SESSION_GATES_2026-10-29.md). **This audit changes docs only.** No application code, test code, dependencies, workflow or README is modified.
