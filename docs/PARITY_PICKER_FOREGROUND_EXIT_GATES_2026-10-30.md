# PR #118: foreground-exit discrimination and real picker cancellation gates (2026-10-30)

Companion [source handoff](UPSTREAM_PICKER_FOREGROUND_EXIT_HANDOFF_2026-10-30.md). **Candidate:** draft PR #118 `edf71ad0c8d06cd6935bd39b2ca586cae8ee65e6`. **Executed evidence:** official-Core [40884881336](https://github.com/xbaconator9000x/PKHeX-Mobile/actions/runs/40884881336) **FAILED** at emulator picker; [40883809973](https://github.com/xbaconator9000x/PKHeX-Mobile/actions/runs/40883809973) previously failed similarly. Existing compile, APK signer, source freeze, backup manifest and media checks passed. All **PF gates below are proposed, NOT executed**.

| Gate | Exact stimulus | Required assertion |
| --- | --- | --- |
| **PF-01 — portable** | Feed the diagnostic classifier four synthetic transitions: (a) app PID unchanged but Activity pauses to Launcher, (b) app PID disappears with native/process exit, (c) new PID replaces old after relaunch, (d) `topResumedActivity=Launcher` alongside stale `mResumedActivity=PKForge`. | Reports distinct outcomes without misclassifying (d) as app foreground or interpreting no Java `FATAL EXCEPTION` as no crash. Logs only allowlisted package/exit-reason classes, not raw crash traces or UI text. |
| **PF-02 — emulator** | On exact signer/SHA-attested APK, sample PID and top-resumed Activity immediately before `adb shell input keyevent 99`, then after it. Bound elapsed time; correlate only new ActivityTaskManager lifecycle events or scoped process exit-info with that transition. | A Launcher result is attributed to either Activity finish/navigation, process exit, a foreground-parser error, or **unresolved** with captured safe evidence. The old intentional `am force-stop` is not misreported as a new crash. No speculative graphics diagnosis. |
| **PF-03 — emulator** | Compare the same single-file route on **fresh app launch** and after the existing Home/background/relaunch negative test. Observe allowlisted first-run dialogue and `Get started`/single-save controls, never raw accessibility XML. | Determine whether a modal still owns input when X is injected; only tap the explicit single-save control or send X when Home is demonstrably active. Do not press blind B/A or silently skip background/relaunch checks. |
| **PF-04 — portable + emulator** | Synthetic logcat: valid current `OPEN_DOCUMENT`, stale valid followed by tree picker, write-grant, wrong category, no launch, and a Launcher foreground. Then actual emulator launch. | Accept only a **fresh** `android.intent.action.OPEN_DOCUMENT` with `CATEGORY_OPENABLE`, read-only request and real DocumentsUI foreground. Reject stale/wrong/tree/write launches and Launcher foreground. No file selected or persisted. |
| **PF-05 — emulator** | From an actual attributed picker, cancel via Back, verify PKForge foreground, repeat a second open/cancel cycle; inject a delayed first result if instrumentation permits. | Both cycles return to the same app without an unintended document URI, grant, source read or write; stale first result cannot bind to second session. The exact-head CI must be green, not just the portable parser tests. |
| **PF-06 — hygiene** | Force UI hierarchy read failure, app exit and malformed XML during PF-02/03; inspect unique shell-private XML path after each case. | Cleanup is confirmed on every path; no `/sdcard` XML, raw UI text, document names, APK or private saves in CI logs/artifacts. |

**Merge threshold for picker claim:** PF-01 and PF-04 portable negatives, PF-02/03 causal diagnosis, and actual PF-05 passing on the same PR head with exact attested APK. If PF-02 is unresolved or PF-05 fails, retain draft PR and `PORT-DEVICE` claim; do not mark it verified. This is not a request to change application write gates, import assets or rewrite upstream UI.

**Evidence status:** the two referenced failures and previously passed compile/signature/manifest checks were executed in CI; **PF-01 through PF-06 have not been run by this audit**. Physical Android, genuine SAF provider reads, cloud/D2D backup restore, retail fixtures, detached Save As and full desktop parity are separate unverified gates.
