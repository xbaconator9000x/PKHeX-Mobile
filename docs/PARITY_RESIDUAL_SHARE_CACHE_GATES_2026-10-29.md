## Minimal implementation strategy

1. Add guards to the existing diagnostic adaptation script for **Showdown file sharing** and **audit-report sharing** before any `File.WriteAllTextAsync`. Do not delete in-app legality/audit display.
2. Make QR rendering in-memory or use unique short-lived diagnostic files with deterministic cleanup; guard the shared `QrPopup` rather than every caller separately. Do not mistake the absence of Android INTERNET permission for QR privacy.
3. Deny park photo sharing in diagnostic mode until legacy photo/asset rights are reviewed. Leave user-generated originals untouched.
4. Add small pinned-source negative fixtures, synthetic C# tests and one actual compiled-adapter assertion. Keep emulator/device work with the owner of [draft PR #83](https://github.com/xbaconator9000x/PKHeX-Mobile/pull/83), avoiding competing workflow edits.
5. After a verified PR, request implementation owner update `development/queue.json` and `development/checkpoint.json` with exact merged SHA and CI URL. Audit must not write those files.

**Acceptance semantics:** `proposed` means specified only; `source-tested` means adapted code and negative fixture executed; `APK-verified` means actual packaged diagnostic policy inspected; `device-verified` requires emulator/physical interaction evidence. No stage proves authenticated retail writes, OEM transfer exclusions or full desktop parity by itself.
