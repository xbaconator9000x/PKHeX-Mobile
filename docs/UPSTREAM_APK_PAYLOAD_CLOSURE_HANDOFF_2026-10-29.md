## New, narrow source-level gaps in PR #65

**P0-A: an APK package name is not an adapted-editor payload attestation.** [`inspect_apk`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/1af1e7360fe4798f36a476118ef0ddd617f9088f/scripts/pkforge_artifact_attestation.py) verifies ZIP CRC, presence of `AndroidManifest.xml`, `aapt dump badging` package name and SHA-256. It does **not** inspect DEX/assemblies, verify a MAUI editor entry point, compare the built archive's assets to the declared source inventory, or bind the package to the transformed source tree. The [synthetic tests](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/1af1e7360fe4798f36a476118ef0ddd617f9088f/tests/test_pkforge_artifact_attestation.py) deliberately use a ZIP with only a synthetic manifest and mocked `aapt2`, which passes the positive attestation test. This is **not evidence that the actual CI APK lacks assemblies**; it proves the attestation does not detect that class of substitution. Fail-closed diagnostic identity is useful but insufficient to certify an installable editor.

**P0-B: the rights inventory is of project-declared inputs, not the final packaged file list.** [`inventory_assets`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/1af1e7360fe4798f36a476118ef0ddd617f9088f/scripts/pkforge_artifact_attestation.py) parses explicit XML `Include` globs from one project, with an unresolved-pattern marker. It does not evaluate imported MSBuild targets/default items, identify transitive resource inclusion, or enumerate and reconcile APK ZIP entries. [Pinned PKForge's project](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/PKForge.App.csproj) explicitly includes PKHeX artwork/sprites, Pokémon Showdown art, Luminescent icons, GameArt/GameHero/GameLogo, BadApple and fonts. The attestation correctly sets `rights_review_complete=false` and `redistribution_authorized=false`. **Do not reclassify these assets as cleared because hashes exist.** For any candidate distributable, produce a rights-clean explicit allowlist and compare actual packaged resources against it, including auto-included assets.

**P0-C: transform provenance is incomplete.** The metadata records source HEADs, adaptation **script hashes**, project hash, NuGet restore graph and APK hash, but no deterministic hash of the **post-transformation source tree**, nor evidence that each intended transform was applied exactly once. An APK with a valid package ID but unexpected editor/writer code could be misidentified. The official-Core workflow applies transforms in order in `/tmp/pkforge`, with read-only tests; retain that pipeline but add a post-transform file manifest, package payload check and reproducible build identity. Treat the attestation as a *non-distribution diagnostic*, as it already states.

**P1-D: two APKs remain distinct.** [`android-build.yml`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/1af1e7360fe4798f36a476118ef0ddd617f9088f/.github/workflows/android-build.yml) uploads `pkhexmobile-readonly-debug-apk` built from `src/PKHeXMobile.Android`; [official-Core probe](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/1af1e7360fe4798f36a476118ef0ddd617f9088f/.github/workflows/pkforge-official-core-probe.yml) builds adapted PKForge temporarily and uploads **only JSON**. Neither workflow presently supplies an installable, rights-cleared adapted editor.

## Shortest safe implementation sequence

1. **Close package evidence gap without publishing art:** generate transformed-tree manifest (changed files and SHA-256), APK entry manifest (path, SHA-256, size, ABI), verify expected MAUI assemblies/entry points, reject missing or unexpected entries and mismatched source/provenance. Keep metadata-only output until rights are cleared. Make the attestation's positive synthetic fixture include representative runtime payload and negative fixtures prove it rejects a manifest-only ZIP.
2. **Produce a minimal rights-clean editor candidate:** remove/replace all unresolved bundled art with original/licensed-neutral placeholders **in the temporary build** and prove an allowlist against actual packaged entries. Audit NuGet transitive licences and GPL source/notice obligations; do not copy ROMs, copyrighted sprites or personal saves. Only then publish a clearly labelled *internal/debug* adapted-editor APK if lawful.
3. **Run device launch and preview:** verify actual install, launcher, party/box selection, detached preview/discard, Back, rotation/recreation and write-denial spy on a synthetic save. Distinguish this from an app that merely compiles.
4. **Only then** execute consented retail/hack differential and desktop oracle; implement independently validated distinct-document Save As with original never truncated. Broaden desktop editor parity after this core transaction.

**Scope:** this audit changes only `docs/UPSTREAM_*` and `docs/PARITY_*`; no application, tests, dependencies, workflows, README, upstream media, keys, ROMs or private saves. The companion [PARITY gate plan](PARITY_APK_PAYLOAD_CLOSURE_GATES_2026-10-29.md) specifies reproducible tests, **not tests executed by this audit**.
