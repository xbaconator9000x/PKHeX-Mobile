# Consolidation handoff: bulk import amplification and session ownership (2026-10-29)

**Decision:** Keep the compiling PKForge MAUI editor, official PKHeX.Core and existing read-only containment. The next smallest safe implementation is **provider-bound session activation and detached preview**, while temporarily disabling unbounded multi-file PKSM imports (or imposing a strict batch budget). Do **not** build another editor or parser. This is a source-level handoff, not Android-device certification.

## P0-A: bounded *per-file* reads do not bound aggregate multi-file import

Pinned [AndroidDocumentPicker.PickManyAsync and HandleMultiResult](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs) have no maximum `ClipData.ItemCount`, no `_pendingMany` cancellation registration, and no read-grant validation before adding each URI. This path is **not** modified by [single-picker lifecycle adaptation](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/5f3f371dd8fba521d148296ef3432afaa0764ac5/scripts/pkforge_picker_lifecycle.py), nor by PR #57's **folder** picker adaptation.

Pinned [PksmTransferFlow.ImportAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/PksmTransferFlow.cs) iterates every returned document, calls `ISaveFileAccess.ReadAsync`, copies each to a new `byte[]`, accumulates them all in `List<(string, byte[])>`, then calls `BuildPlans(files)`. The [two-open source wrapper](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/5f3f371dd8fba521d148296ef3432afaa0764ac5/scripts/pkforge_source_read_hardening.py) caps **each** source to 32 MiB, but does not cap **count or aggregate retained bytes**. For example, 64 files of 32 MiB can retain ~2 GiB of payload alone, before provider buffers, snapshots, plan decoding and copies. This is a source-derived worst-case allocation estimate, **not** a measured device OOM. Provider UI may impose limits, but none is enforced in this code.

**Fast fix:** In preview-only builds, disable `PickManyAsync`/PKSM import UI until a tested cap exists, **or** enforce both a small maximum document count and an aggregate byte budget *before* retaining or decoding each file; reject excessive `ClipData` counts before allocating the URI list, stop and dispose on cancellation, and require an actual read grant. A 32 MiB per-file cap alone is insufficient. Do not let the bank-import feature delay provider-bound nickname preview.

## P0-B: session activation has no latest-request-wins ownership

Pinned [SaveSessionService.OpenAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SaveSessionService.cs) awaits the source read, selects a format using persisted user choice, opens an engine session, calls `MakeActive()`, disposes the old `CurrentSession`, then assigns `CurrentSession` and `Current`. There is no monotonic generation/operation ID or post-parse cancellation check. `Close()` and `RevertToBaseline()` do not invalidate an in-flight `OpenAsync`. If open A is delayed while B completes, A can activate last; if Close occurs while A is pending, A can reactivate after Close. This is a **source-level concurrency inference**, not an executed race. If the engine has global active state, the activation order matters even more; test it instead of assuming.

The already implemented [SaveDocumentSession](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/5f3f371dd8fba521d148296ef3432afaa0764ac5/src/PKHeXMobile.Domain/SaveDocumentSession.cs) can independently reopen and compare immutable bytes and optional opaque provider identity. It does **not** itself impose generation ordering or certify a retail layout. Integrate it as a source boundary, with a single serialized activation/close/revert gate and a generation increment on every new open/close/revert. On a stale completion, dispose the candidate without `MakeActive()` or overwriting `Current`. Do not use user-selected `GameChoiceId` as retail authentication.

## P0-C: UI preview still serializes the mutable engine session

The [temporary MAUI preview injection](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/5f3f371dd8fba521d148296ef3432afaa0764ac5/scripts/pkforge_detached_preview_ui.py) calls `SaveInputSnapshot.FromBytes(session.Serialize().Span)` and shows the resulting overlay after `await`. The existing [DetachedRetailNicknameEditor](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/5f3f371dd8fba521d148296ef3432afaa0764ac5/src/PKHeXMobile.PortConsolidation/DetachedRetailNicknameEditor.cs) performs detached synthetic editing and source fingerprint checks, but has no provider identity/generation binding. Thus a mutable/normalized session can become the supposed baseline and a late overlay can display under a new selection. Neither issue grants file-write permission; both block trustworthy editing and eventual Save As.

**Fast fix:** Capture immutable provider-origin bytes, optional identity, URI and generation once per verified open; pass *that* snapshot to the existing detached editor. Recheck generation, slot, URI and source fingerprint before displaying a preview, and independently reopen the provider before any later publication. Keep original-document writes denied.

## P1-D: folder enumeration is still unbounded

PR #57 caps **folder file reads**, not [AndroidFolderFileAccess.QueryChildren/ListFiles](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidFolderFileAccess.cs). `QueryChildren` loops `cursor.MoveToNext()` into a list without a count limit; `ListFilesAsync` uses `Task.Run(() => ListFiles(treeId), token)`, but does not check cancellation inside enumeration. A very large/misbehaving provider could cause long-running enumeration or large allocation. This is an unexecuted source-level risk. Apply an entry cap, cancellation checks in the loop, and a clear user-facing refusal, or disable folder import until tested.

## Smallest implementation batch, in order

1. **Do not expand audits into new game systems.** Disable PKSM multi-import/folder import temporarily if bounded-count and cancellation work would delay the real editor; PR #57's writer containment must remain intact.
2. Add provider-bound immutable source and **latest-request-wins** activation to the existing PKForge `SaveSessionService`, with cancellation/close/revert and stale parse disposal tests.
3. Rewire the existing MAUI nickname preview from `session.Serialize()` to provider-original snapshot, check selection generation after every await, and verify cancel/discard leaves all live state unchanged.
4. Only after real retail and valid-looking hack differential tests, introduce distinct-destination staged Save As with alias refusal, independently reopened readback and original-source recheck. No original URI writes.
5. Then selectively add desktop editor parity. Full desktop parity, ROM-hack writes, real Android device tests and signed release are still missing.
