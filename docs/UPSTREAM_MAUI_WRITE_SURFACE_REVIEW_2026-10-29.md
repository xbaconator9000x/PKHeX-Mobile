## P0 finding: the temporary MAUI editor compiles with the original in-place save action still exposed

1. Our [temporary UI transformer](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/4a2fc420367bb12beff1cbb794a0cc2858ba1f6a/scripts/pkforge_detached_preview_ui.py) inserts `detachedPreview` **before** the existing `var save = FocusButton(EditorTool("Save changes"...))` anchor, and replaces `panel.Children.Add(save)` with `panel.Children.Add(detachedPreview); panel.Children.Add(save)`. It **does not remove, disable or redirect the original Save changes control**.
2. Pinned upstream [`BoxBrowserPage.cs`, around lines 4527–4529 and 4645](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/BoxBrowserPage.cs#L4527-L4529) binds that original control to `BoxBrowserViewModel.SaveEditCommand`. The same file contains other mutation entry points (e.g. `RunMutationAsync` and sub-editors); hiding one button alone would **not** establish a non-publishing shell.
3. Pinned upstream [`BoxBrowserViewModel.cs`, lines 205–279](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/ViewModels/BoxBrowserViewModel.cs#L205-L279) applies an edit to a **live session**, serializes, then calls `_writer.WriteScopedAsync(session.Document.DocumentId, ...)`. Its [`RunMutationAsync`, lines 431–481](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/ViewModels/BoxBrowserViewModel.cs#L431-L481), calls `_writer.WriteAsync`, including a user-confirmed suspected-hack path. Party/box moves have an additional [scoped writer call near line 887](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/ViewModels/BoxBrowserViewModel.cs#L880-L889).
4. Pinned [`SafeSaveWriter.cs`, lines 142–144](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SafeSaveWriter.cs#L142-L144) delegates to `access.WriteAtomicallyAsync(documentId, candidate)`. On Android [`AndroidSafFileAccess.cs`, lines 24–37](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs#L24-L37) opens the **same document URI** with `OpenFileDescriptor(uri, "rwt")` and truncates/writes. That is not a portable atomic replacement and can damage the original on interruption. A backup is useful but does not make original-file truncation safe.

**Precise scope:** this is a **source-proven reachable writer path in the temporary PKForge MAUI checkout if the compiled UI were used with a writable save**. There is **no evidence of an actual write or corruption in CI**. The shipped native [PKHeX Mobile `MainActivity.cs`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/4a2fc420367bb12beff1cbb794a0cc2858ba1f6a/src/PKHeXMobile.Android/MainActivity.cs) remains read-only and does not contain this MAUI preview screen. Therefore neither “our released app corrupts saves” nor “the preview is device-tested” follows from this audit.

**Implementation instruction:** before enabling any temporary MAUI editor for device tests, install a **write-denying `ISafeSaveWriter` at the dependency-injection/service boundary** for *all* commands and routes; optionally hide or relabel save controls for UX, but never rely on visibility alone. Only a separately audited Save As service may later receive write authority. This is a smaller and safer adaptation than rewriting the editor.

## P0 finding: preview provenance is an in-memory serialization, not an authenticated provider snapshot

Our [transformer `adapt_view`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/4a2fc420367bb12beff1cbb794a0cc2858ba1f6a/scripts/pkforge_detached_preview_ui.py) obtains `SaveInputSnapshot.FromBytes(session.Serialize().Span)` from `_sessionsFor()`, then calls [`DetachedRetailNicknameEditor.Preview`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/4a2fc420367bb12beff1cbb794a0cc2858ba1f6a/src/PKHeXMobile.PortConsolidation/DetachedRetailNicknameEditor.cs). The adapter correctly makes independent copies, checks retail layout and unchanged round-trip, scopes one edit, reopens the candidate and refuses publishing. However the bytes it receives could already include unsaved changes made to PKForge's **live** session by another editor control. It does not read an independently authenticated source URI, compare against a fresh provider fingerprint or bind the candidate to a document identity.

This is a **proven provenance gap**, not proof that a particular preview corrupts bytes. Do not reuse the preview's `SourceFingerprint` as proof of on-disk identity. Show “Preview from current in-memory session” until a separately captured immutable provider snapshot is passed. Cancel/discard must not invoke any mutation or publication path. Race tests must interleave selection changes, another editor's mutation and document replacement.

## Minimal implementation handoff — no additional broad audits

**Batch A, before any device preview:** inject a fail-closed writer for all `ISafeSaveWriter` calls in the temporary MAUI build; hide existing Save changes and mutation actions or make them explicitly preview-only; add a synthetic read-only provider spy that throws on *every* attempted write. Keep official Core and PKForge's working editor. Verify a negative test that intentionally invokes `SaveEditCommand`, `RunMutationAsync` and a move and proves the source hash unchanged.

**Batch B, actual UI:** bind one authenticated retail source snapshot to one selected slot and the detached adapter; preview nickname, before/after, legality and explicit Cancel. Test selection switching while preview pending and dirty in-memory sessions. Capture emulator/device launch and navigation; a Linux MAUI compile is insufficient.

**Batch C, distinct-document Save As:** implement a new service using a separate destination URI; refuse same/aliased source, stage and reopen destination, verify candidate hash/structure/allowed diffs, re-open source independently before and after, report partial destinations accurately. Keep ROM-hack and unknown layouts read-only. Enable per-format writes only after positive same-Core/desktop tests.

**Status:** source-reviewed P0 exposure, **not yet mitigated** in the inspected `main`. No device, provider, Save As, or desktop-oracle test was executed by this audit. A 30-productive-hour delivery goal is a target, not proof of parity. This file and its companion are the only intended audit changes; implementation ownership remains with the separate code agent.
