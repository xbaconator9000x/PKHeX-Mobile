## P0-A: read-only preview still requests and may persist **write** permission

Pinned [`AndroidDocumentPicker.PickSaveAsync`](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs#L13-L38) launches `ACTION_OPEN_DOCUMENT` with `GrantReadUriPermission | GrantWriteUriPermission | GrantPersistableUriPermission`. Its single-file [result handler](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs#L78-L109) calls `AndroidSafFileAccess.PersistPermission(uri, data)`. The latter [takes both returned read and write flags](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs#L44-L52). In contrast, the upstream **multi-file** picker requests read/persistable only.

Our [PR #50 containment](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/8cc94a06ab90ef8fc2e962e42f5da90193df3923/scripts/pkforge_readonly_containment.py) replaces `ISafeSaveWriter` and `ISaveFileAccess` registrations, but does **not** change `IDocumentPicker`, the Android picker or its static permission helper. Thus the read-only app's single-file picker can still request unnecessary write capability; when granted, it can persist it. This is a source-proven **least-privilege gap**, **not evidence that any file was written**. A denied writer is not a substitute for read-only Android URI grants.

**Smallest safe adaptation:** in the temporary pinned MAUI checkout, change the single-save picker to request `GrantReadUriPermission | GrantPersistableUriPermission` only; persist only a confirmed read grant, even if a provider returns additional flags. Never request or persist write permission for source documents. Keep `ACTION_CREATE_DOCUMENT` for a future separately authenticated Save As destination. Preserve the existing read-only service barriers.

## P0-B: failed move can leave the **live session dirty** despite writer refusal

The pinned [`BoxBrowserViewModel` move/drop path](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/ViewModels/BoxBrowserViewModel.cs#L830-L911) executes `engineSession.MoveSlot(...)`, calls `BumpMutationGeneration()`, updates visible slots, serializes, and **only then** calls `_writer.WriteScopedAsync`. The `catch (Exception error)` logs and sets status, but **does not call `DiscardPartialEdits()` or `_sessions.RevertToBaseline()`**. A read-only writer refusal therefore leaves a plausible path to changed in-memory party/box data even though the original file remains untouched. The preview injection obtains bytes via `SaveInputSnapshot.FromBytes(session.Serialize().Span)`, so a later nickname preview could operate on these uncommitted bytes.

This is a source-proven rollback omission, **not an executed assertion of a particular dirty state**. Contrast the pinned [`SaveEditAsync`](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/ViewModels/BoxBrowserViewModel.cs#L206-L291) and [`RunMutationAsync`](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/ViewModels/BoxBrowserViewModel.cs#L431-L535): both call `DiscardPartialEdits()` on exceptions. [`SaveSessionService.RevertToBaseline`](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SaveSessionService.cs#L35-L59) reopens the baseline and upstream [tests](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/tests/PKForge.Engine.Tests/SaveSessionServiceTests.cs) already exercise reverting a partial edit.

**Fastest safe implementation:** while the MAUI app is preview-only, **block mutating commands before `ApplyEdit`, `MoveSlot`, bulk operations or any live-session mutation**, including keyboard/gamepad paths. Keep the detached nickname preview, which does not mutate the live session. If allowing experimental moves later, serialize them through a single transaction/generation lock, revert on every refused or failed publication, and invalidate queued moves before refreshing UI. Simply adding a `catch` rollback to the existing concurrent move loop without reasoning about `_movesInFlight`, `_moveWrites` and `_serializing` may roll back another operation; test interleavings first.

## P0-C: two DI barriers are real but not a complete capability sandbox

PR #50 [`ReadOnlySaveWriter`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/8cc94a06ab90ef8fc2e962e42f5da90193df3923/scripts/pkforge_readonly_containment.py) rejects `WriteAsync` and `WriteScopedAsync` including `WriteScope.Everything`, and `ReadOnlySaveFileAccess` rejects `WriteAtomicallyAsync`. The [CI smoke](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/8cc94a06ab90ef8fc2e962e42f5da90193df3923/tests/PKHeXMobile.Containment.Smoke/Program.cs) proves those service methods refuse with a fake provider spy. It does **not** prove that every upstream code path uses those DI services or that Android picker permissions are read-only. A direct `new AndroidSafFileAccess()` or direct `ContentResolver` write would bypass the DI wrapper if reachable. This is a **residual audit/test requirement**, not a confirmed bypass. Do not label this build a security sandbox or an Android provider certification.

The [read-only MAUI adaptation](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/8cc94a06ab90ef8fc2e962e42f5da90193df3923/scripts/pkforge_detached_preview_ui.py) disables the legacy Save changes control, but other mutation controls remain. The most efficient next batch is picker least privilege + mutating-command lockout + **actual view-model refusal and session rollback smoke**, rather than more editor inventory.

## Implementation order and stop conditions

1. **One cohesive preview-containment batch:** read-only picker grants, pre-mutation command lockout for all UI/gamepad commands, explicit `Cancel`/discard, and tests proving `session.Serialize()` equals its baseline after denied move/edit/bulk attempts. No changes to original save or other user documents.
2. **Provider-bound preview:** capture immutable original bytes and URI/grant metadata, two independent reads/fingerprints, stale-selection checks, and separate scratch edits. Show an honest *in-memory preview* label until this is proven.
3. **Detached Save As:** user-selected *distinct* destination URI, reject same/aliased source, re-read source before and after, independently validate/reopen candidate and destination, handle cancellation, partial files and providers that ignore flags. Never publish through the original `rwt` writer. Unknown hacks remain read-only.
4. **Only then broaden feature parity** with reusable PKForge UI and selective PKHeX MAUI screens; do not import unlicensed assets or fork-only Core behavior.

**Execution status:** this audit inspected source and GitHub CI results; **it did not execute new runtime or device tests**. No application/test/workflow/dependency/README changes in this documentation batch. No evidence of actual save corruption or successful source writing. The 30-hour goal remains aspirational; no release or full desktop parity is certified.
