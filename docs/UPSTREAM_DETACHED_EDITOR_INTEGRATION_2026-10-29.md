## Newly exposed P0/P1 issues, without overstating findings

1. **P0 product integration:** positive detached edit exists only in the external checkout's test process; there is no UI path from the shipped native read-only Android app to the adapter. Treat “editor working on Android” as **false** until an actual Android UI calls it and an emulator/device test demonstrates selection, preview and cancel.
2. **P0 transaction boundary:** `RetailNicknamePreview.CopyCandidateBytes()` deliberately makes candidate bytes available but does not bind a live provider identity or grant publication authority. Before any Save As, the caller must prove source fingerprint freshness through a **fresh independent source open**, authenticate layout, verify approved changed ranges and re-open the written destination. Never wire raw preview bytes directly to SAF output.
3. **P0 detection coverage:** Gen 6 X positive plus invalid Unbound negative cannot establish safe writes across games or ambiguous ROM hacks. In particular the BEEF footer is inserted into a synthetic blank fixture to make it parser-recognizable; it is **not** a real cartridge dump or independent format oracle.
4. **P1 edit semantics:** current nickname validation checks nonempty, non-whitespace and `<=64` C# characters; actual per-generation nickname encodings, glyph validity, trash bytes and nickname flags require independent same-Core verification. The reopen equality check helps detect truncation but does not establish semantic equivalence or legality.
5. **P1 global context:** upstream `SaveEngineSession` calls static `LegalityRules.Apply()`; `MakeActive` changes process-wide `ParseSettings`. The adapter does not call `MakeActive`, but UI adoption must prevent unrelated sessions and concurrent previews from contaminating context. This is a **testable risk**, not a demonstrated bug.

## Minimal safe integration order

**One implementation batch** should: (a) expose one editor view in the adapted PKForge Android shell, selecting one *authenticated retail* box slot; (b) invoke the already tested detached preview and show before/after nickname and legality, with Cancel/discard leaving original bytes untouched; (c) add synthetic Gen 6 positive/negative UI and source-race tests, and capture a real Android emulator launch/navigation result; (d) keep Save As disabled until a separate distinct-document provider test suite passes. Reuse upstream view-model bindings and Engine contracts rather than writing another save parser or bespoke editor.

**Next release blocker:** a provider-safe Save As and desktop-matched positive fixture. Neither is certified by the 14-assertion smoke. Expand other PKForge/MAUI editors only after this vertical slice works. Do not count proposed gates as executed or equate the 30-productive-hour target with a verified completion forecast.
