## Fastest safe path, in implementation order

1. **Do not start over.** Keep the passing pinned PKForge Android MAUI build as the shell/UI reference. Keep the existing native Android official-Core reader and fail-closed staging contracts as a known-good fallback. Preserve all upstream source at immutable revisions.
2. **One compile-boundary patch in a temporary pinned checkout:** isolate fork-only Luminescent and Compass code paths into optional hack modules or compile-time-disabled adapters *without changing retail parsing behavior*. Prefer removing these references from the retail build graph rather than faking missing Core symbols. Run `dotnet build src/PKForge.Engine/PKForge.Engine.csproj -c Release` with exact `[26.10.18]`, and separately build Android. No production source swap until both pass.
3. **One detached retail edit flow:** reuse PKForge party/box editor UI and bindings; parse with the official Core; clone PKM/save state before edit; show legality, preview and cancel without mutating source. Use the independent existing preflight contracts. Do not route through in-place SAF `rwt`.
4. **Save As-only publishing:** distinct URI, independent reopen and source hash recheck, desktop-oracle slot/checksum comparison, interrupted-provider tests. Disable Save/replace-original until proven. The prior [16 P0 gates](PARITY_PORT_CONSOLIDATION_GATES_2026-10-29.md) remain mandatory.
5. **Then broaden** format support and cherry-pick MAUI-specific editor tabs. PKHeX MAUI pinned [project](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/PKHeX.MAUI.csproj) targets Android via MAUI but references `PKHeX.Core 26.7.7` and separate binaries; **ADAPT selected UI, not its Core package or unchecked binaries**. Official desktop [PKHeX](https://github.com/kwsch/PKHeX/tree/7e26bc53215e4f7bc0041ca375f1042539cb81b3) remains the feature oracle; the **actual engine release** is [`26.10.18`](https://github.com/kwsch/PKHeX/tree/bfe89c74a3f5265805e364b79bc04ad38ebbc5ea).
