# PKForge activation transaction handoff — 2026-10-29

**Decision:** Keep the already-compiling PKForge Android MAUI shell, its adapted official-Core engine and the existing provider-origin detached editor. **Do not rewrite the editor.** The next smallest P0 batch is to make *session activation* atomic with close/revert/new-open and to disable or budget PKSM bulk import. This is a source-backed implementation handoff, **not** an Android/device/save-writing certification.

## Newly isolated P0: generation check is not an activation transaction

The [exact pinned transformation](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/bb57c444166515b7406f14d2a38302e503ba88a0/scripts/pkforge_provider_origin_binding.py) adds `_openingGeneration` to PKForge's [SaveSessionService](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SaveSessionService.cs). After awaiting `access.ReadAsync`, it creates `engineSession`, checks `request != Interlocked.Read(ref _openingGeneration)`, and then calls `engineSession.MakeActive()`, disposes `CurrentSession`, and assigns `CurrentSession`, `Current` and `ProviderOrigin`. **There is no synchronization spanning that check and the activation/assignment.**

A concurrent Open B or Close can increment the generation *after* A's check but *before* A commits, allowing A to activate or publish stale state. This is a source-level interleaving possibility, **not a reproduced failure**. The [new lifecycle smoke](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/bb57c444166515b7406f14d2a38302e503ba88a0/tests/PKHeXMobile.ProviderOriginLifecycle.Smoke/Program.cs) deliberately stalls A at the **first read**; it does not stall after A's final generation check, inside `MakeActive`, or during session assignment. The passing smoke therefore closes the *read-order* race, not the *activation commit* race.

**Second gap:** the transform increments `_openingGeneration` on Open and Close, but `RevertToBaseline()` and `MarkWritten()` only clear `ProviderOrigin`. A previously started slow Open can still activate after Revert; a hypothetical future write-notification route also lacks a generation fence. Revert remains a live engine replacement and must participate in the same ownership epoch. The preview-only writer is already denied; this is a lifecycle/preview concern, **not evidence of an original save write**.

**Third gap:** the source calls `engineSession.MakeActive()` before replacing the previous session and has no `try/finally` around the candidate after `OpenSession`. If activation or snapshot creation throws, the candidate may remain undisposed or global active-engine state may be affected. Verify with fault-injection, do not assert a leak or global-state corruption without a test.

**Smallest safe fix:** keep the PKForge `SaveSessionService`, but serialize activation, close and revert through one ownership gate (async-safe for the read/parse phase; a short synchronous critical section for validation/activation/commit). Increment epoch for every invalidating operation; check the epoch *inside* that critical section immediately before `MakeActive`; publish `Current`, `CurrentSession` and `ProviderOrigin` as one logical transaction; dispose stale/faulted candidates. No lock held across provider I/O. Do not re-enable original-file writes.

## Existing, not newly discovered, release blockers

- **Multi-file PKSM import**: [prior audit](UPSTREAM_BULK_IMPORT_SESSION_HANDOFF_2026-10-29.md) found an unbounded `ClipData` count and aggregate retained file bytes despite a 32 MiB per-file cap. PRs #59–60 do not touch the importer. Disable the user-facing bulk path now, or enforce both count and total-byte budgets plus cancellation/grant tests. Do not delay the single-Pokémon editor for this optional import.
- **Provider identity**: [ProviderBoundRetailNicknameEditor](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/bb57c444166515b7406f14d2a38302e503ba88a0/src/PKHeXMobile.PortConsolidation/ProviderBoundRetailNicknameEditor.cs) compares source bytes and an opaque document ID but explicitly does **not** authenticate provider generation/identity. The existing [SaveDocumentSession](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/bb57c444166515b7406f14d2a38302e503ba88a0/src/PKHeXMobile.Domain/SaveDocumentSession.cs) supports an optional identity-bearing read handle. Adapt that seam before any publication; matching bytes alone do not prove retail layout.
- **Overlay timing**: [MAUI injection](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/bb57c444166515b7406f14d2a38302e503ba88a0/scripts/pkforge_detached_preview_ui.py) checks selection and request generation immediately before `await PadMenu.ShowAsync`; verify what happens when the app navigates/closes *while* the overlay is pending. No observed stale overlay is claimed.
- **Retail/hack differentiation and Save As**: only synthetic Core fixtures have been exercised. Authentic positive retail saves and valid-looking same-size ROM-hack negatives, independently checked slot scope, distinct-destination identity/alias, staged output readback and Android interruption tests remain release blockers.

## Implementer handoff: no further general audit loop

1. **One PR:** short session activation/close/revert transaction gate plus deterministic post-check interleaving tests against the **actual transformed PKForge service**. Keep the existing passing PR #59/#60 smoke tests.
2. **Same or next PR:** disable PKSM bulk import until bounded and lifecycle-tested. This is an optional feature; no reason to let it block editor preview.
3. **Next milestone:** Android provider/device smoke and real retail/hack differential. Then independently validated **Save As to a new destination only**; preserve denial of in-place writes.
4. Add desktop editor tabs only after the source-to-output transaction works. Report actual feature coverage, not percentages inferred from files.
