## Current implementation delta — four specific gates

**ECR-01 (P0) — the new attested APK selector is not wired into the emulator runner.** Main [`scripts/pkforge_emulator_apk_selection.py`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/6fde96577de69d4fd9d9ac2e6ecb5b2f0c5e67c0/scripts/pkforge_emulator_apk_selection.py) from [PR #103](https://github.com/xbaconator9000x/PKHeX-Mobile/pull/103) verifies a unique signed APK filename, source commit, frozen-source hash syntax, package identity, APK byte size/SHA-256 and symlink refusal. Its [synthetic tests](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/6fde96577de69d4fd9d9ac2e6ecb5b2f0c5e67c0/tests/test_pkforge_emulator_apk_selection.py) run in Foundation. But draft [PR #83](https://github.com/xbaconator9000x/PKHeX-Mobile/pull/83) still adds `scripts/pkforge_emulator_launch_smoke.sh` with `find ... -name '*-Signed.apk' -print -quit` and an unsigned fallback. The existing official-Core workflow on main [produces provenance metadata only](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/b2e1a6005f96026a20b4bc38230053305e8663d0/.github/workflows/pkforge-official-core-probe.yml#L333-L350), and does **not** install a selected APK. **Handoff:** rebase #83, invoke the existing selector with the same-run `$RUNNER_TEMP/pkforge-diagnostic-provenance.json`, `--build-dir /tmp/pkforge/src/PKForge.App/bin/Debug/net10.0-android`, and the checked-out exact Git commit SHA, then install only its JSON `path`. Verify SHA-256 again immediately before `adb install`. Do not use `--variant single` as an implicit unsigned fallback. Keep provenance private and APK non-distributable.

**ECR-02 (P0) — draft #83's legacy queue claim is not resumable by the new selector.** PR #83's queue patch sets `PORT-APK.status=in_progress` with loose `claim_branch` and `claim_base_sha` fields; it does not include the required nested `claim: {branch,pr,base_sha}`. Current [`scripts/development_queue.py`](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/b2e1a6005f96026a20b4bc38230053305e8663d0/scripts/development_queue.py) only recognizes an exact nested claim for `--resume`; `in_progress` tasks without a matching claim are reserved and not selected. Its validator currently does **not** reject legacy extra fields or require `claim` on every in-progress task. Thus merging #83's stale queue hunk would risk a **permanently unresumable PORT-APK lock**, even if the rest of CI passed. **Handoff:** remove/reconcile old queue hunks during rebase and claim through a fresh, reviewed implementation-owned PR with the exact PR number, branch and base SHA, or keep PORT-APK ready until an authorized claim exists. Never force-resume or bypass lock checks.

Rebase on current main, retain PR #101's trigger coverage and add emulator selector/script/test paths only as needed; run exact-head Foundation, queue and official-Core CI.
