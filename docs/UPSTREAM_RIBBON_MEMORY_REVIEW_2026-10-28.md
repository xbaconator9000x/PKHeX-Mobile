## Implementation order and acceptance handoff

1. **P0 — prevent silent data changes:** no in-place edits, no mutable shared modal state, no unvalidated ribbon indices, no no-op memory rewrite, no mutation-on-text-change; retain immutable document fingerprint and source entity bytes.
2. **P1 — read-only parity:** expose typed ribbon/mark counts, title index, Pokérus and memory OT/HT with exact format context, source-version labels, raw values and unsupported states. Preserve source bytes. The index range and numeric-ribbon differences above should be regression tested before any Android UI claims.
3. **P1 — legality and history:** distinguish ribbon existence, encounter obtainability, ownership, title eligibility, memory legality and source save authentication. A legal ribbon does **not** authenticate a save layout or permit export.
4. **P1 — independent proof:** build matching pinned desktop Core, generate rights-cleared synthetic and consented fixtures, compare every field plus untouched bytes and checksum/block behavior, then test Android provider interruption and rollback.
5. **Licensing and packaging:** review each image/font/sprite family separately, including any inherited PKHeX, PKSM, game artwork and third-party art; do not copy assets from these upstream apps into mobile without provenance.

## Testability, non-claims and safety

The companion [pass K parity gates](PARITY_RIBBON_MEMORY_GATES_2026-10-28.md) define **36 proposed scenarios**, all unexecuted in this audit. Tests must run both debug and release/trimming builds where reflection is involved. Use synthetic entities and independently produced desktop oracles; never commit commercial ROMs, proprietary art, user saves, personal data, credentials or chat transcripts. Any unsupported or modified ROM-hack layout remains read-only regardless of ribbon/legality results. Only audit-owned documentation was changed.
