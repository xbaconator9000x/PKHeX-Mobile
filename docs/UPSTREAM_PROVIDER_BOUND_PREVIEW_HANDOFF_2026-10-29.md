## P0-1: PKForge's source read remains unbounded and single-open

Pinned [AndroidSafFileAccess.ReadAsync, lines 14–22](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs#L14-L22) calls ContentResolver.OpenInputStream, then copies the **entire** provider stream into MemoryStream via CopyToAsync. No byte cap or independent second open is applied there. The PR #52 [read-only wrapper](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/932feafa2b0350691520d4e8a9dcb06cae9c94ef/scripts/pkforge_readonly_containment.py) delegates ReadAsync to that original reader unchanged. An arbitrary oversized or nonterminating provider stream can therefore consume unbounded memory or stall reading; the source proves the absence of a bound, **not an observed OOM**. CancellationToken on CopyToAsync does not necessarily cancel the preceding synchronous provider open.

Pinned [SaveSessionService.OpenAsync, lines 16–28](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SaveSessionService.cs#L16-L28) reads **once**, picks a format from a persisted user choice, opens an engine session, calls MakeActive, then replaces CurrentSession. It does not independently re-read the provider and compare bytes/identity before promotion. The retail-only parser [rejects known hack signatures](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/932feafa2b0350691520d4e8a9dcb06cae9c94ef/scripts/pkforge_retail_only_probe.py), but that is not an authenticated positive retail-layout proof and does not resolve a provider race.

**Fastest reuse:** use our already implemented [SaveInputSnapshot bounded reader (32 MiB maximum)](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/932feafa2b0350691520d4e8a9dcb06cae9c94ef/src/PKHeXMobile.Domain/SaveInputSnapshot.cs), [SaveDocumentSession two-open and identity comparison](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/932feafa2b0350691520d4e8a9dcb06cae9c94ef/src/PKHeXMobile.Domain/SaveDocumentSession.cs), and [Android read-only descriptor with CancellationSignal](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/932feafa2b0350691520d4e8a9dcb06cae9c94ef/src/PKHeXMobile.Android/SafReadStream.cs) as **adapters** around the PKForge picker/session, rather than writing a second Android provider stack. The existing SafReadStream is internal to the native Android project, so an integration seam/refactor is needed. A stable authority/document ID is only an opaque identity hint; two matching reads do not prove retail layout or authorize writes.

## P0-2: detached nickname preview is still derived from a mutable serialized session

The [temporary UI injector](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/932feafa2b0350691520d4e8a9dcb06cae9c94ef/scripts/pkforge_detached_preview_ui.py) constructs SaveInputSnapshot.FromBytes(session.Serialize().Span) inside the button handler. This is **not the original provider byte stream**. PR #52 blocks the three recognized live mutation families in BoxBrowserViewModel, substantially reducing dirty-session risk, but a serialization can still differ from the originally opened document and does not carry source URI, provider identity or read-grant evidence. The [detached editor](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/932feafa2b0350691520d4e8a9dcb06cae9c94ef/src/PKHeXMobile.PortConsolidation/DetachedRetailNicknameEditor.cs) correctly labels its candidate non-publishing; RequireMatchingSource compares content fingerprints only.

**Fastest reuse:** hold a private immutable provider-origin SaveInputSnapshot alongside PKForge's existing session. Verify the provider on a second open **before** making the session visible, bind preview to the original snapshot and a selection generation, reverify before/after preview when practical, and invalidate it on picker cancellation, replacement, revoke or navigation. Never use session.Serialize as the source-of-truth for export authorization. No need to rewrite PKForge's box UI, editing engine or legality presentation.

## P1-3: picker cancellation and read-grant fallback need real lifecycle tests

Pinned [AndroidDocumentPicker.PickSaveAsync, lines 14–32](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs#L14-L32) registers cancellation and then returns _pending.Task. If the token is **already cancelled**, registration may synchronously clear _pending, after which the code still launches the picker and dereferences _pending.Task. This is a source-level null-dereference/lifecycle hazard, not an executed crash. Cancellation after launch also leaves the external picker outstanding; late results must never attach to a newer selection. The [single-result handler](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs#L94-L116) treats any failure to persist the grant as a picker failure, whereas its multi-picker path tolerates read-once fallback. PR #52 now persists read only; a provider lacking persistable grants still needs a defined read-once policy or explicit refusal.

**Minimal fix:** reject pre-cancelled tokens before starting an intent, keep a local TaskCompletionSource independent of the mutable field, use an operation/generation ID to reject late results, and deliberately support read-once or fail closed with a clear message. Do not request write permission to fix a provider compatibility issue.

## Implementation order: shortest verified critical path

1. **One bounded source-adapter batch:** replace unbounded PKForge ReadAsync with our bounded/cancellable provider reader, two independent opens and immutable baseline; refuse stale/revoked/oversized/ambiguous input. Keep the existing read-only writer barriers.
2. **One provider-bound preview batch:** source snapshot + identity/generation context, PKForge UI binds to that snapshot, cancellation discards it, no live-session serialize as authority. Prove no mutation on cancel/refusal and no stale preview after switching documents.
3. **One Android runtime batch:** install diagnostic build, launch, pick/read/cancel on at least a local SAF provider and one non-file provider, exercise permission revocation and background/resume. Record device/OS/provider; compiling MAUI alone is not enough.
4. **Only after those gates:** separate Save As with independently authenticated retail format, byte scope, source recheck, destination alias rejection, candidate reopen and destination readback; unknown hacks stay non-writing. Broaden PKForge and selected MAUI editor features afterward.

**Status:** source-level findings plus inspection of existing CI only. This audit did not run new Android instrumentation, authenticated retail save fixtures, or export tests; it makes no claim of device certification, Save As, full desktop parity, or a reliable 30-hour completion forecast. No application, test, dependency, workflow or README files are modified by this audit.
