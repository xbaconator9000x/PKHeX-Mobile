Current PKHeX-Mobile [`ReadOnlySaveInspector.TryInspect`](../src/PKHeXMobile.ReadOnly/ReadOnlySaveInspector.cs) returns `SupportedReadOnly` for recognized saves with Core-valid checksums and bounded party/box counts. That label means **provisional parsing**, not verified retail identity or hack exclusion. A ROM hack may have the same retail envelope. The app must visibly distinguish `parsed by Core` from `verified profile`, and never expose an export action based on that property.

## Additional MAUI implementation-body findings (pinned source)

1. **P1-MAUI-ITEMS-01, no-op copy target:** [`SaveEditors/Items.xaml.cs`](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/SaveEditors/Items.xaml.cs) uses expressions such as `data?.ToArray()[0].CopyTo(za.Items.Data.ToArray(), 0)` in its remote inventory read branch (Gen 6–9). `Items.Data.ToArray()` is a **new array**, not the original inventory storage. The copied bytes therefore do not update that destination array in this code path. This is a source-level observation, not a remote-device reproduction. **Test:** inject a distinct byte pattern, compare the live `Items.Data` before/after and ensure a validated write to the intended buffer. Do not port this pattern.
2. **P1-MAUI-BATCH-01, error does not stop mutation:** [`boxtab/BatchEditor.xaml.cs`](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/boxtab/BatchEditor.xaml.cs) shows an alert when a parsed batch set has zero instructions but does **not** return, and subsequently runs `ProcessSAV` and writes cached slots. This is a potentially unsafe control-flow path, not proof of actual data corruption. **Test:** empty/malformed instruction sets must make zero writes and retain a byte-identical original.
3. **P2-MAUI-NAV-01, always-true visibility condition:** [`SaveEditors/Save Editors.xaml.cs`](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/SaveEditors/Save%20Editors.xaml.cs) sets `TrainerInfoButton.IsVisible = (sav is not SAV8BS || sav is not SAV8SWSH || sav is not SAV7b)`. A save cannot be all three types at once, so this OR condition is true for every non-null save. Do not copy visibility gates without per-format navigation tests. The same file routes Gen 1–5 to a shared `TrainerEditor1`; the [editor implementation](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/SaveEditors/Gen1/TrainerEditor1.xaml.cs) contains per-generation branches, so **shared routing is not by itself a bug**.
4. **P2-MAUI-TRAINER-01, BP cap candidate:** [`SaveEditors/Gen1/TrainerEditor1.xaml.cs`](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/SaveEditors/Gen1/TrainerEditor1.xaml.cs) `MaxBP` sets `BPEntry.Text` to `MainPage.sav.MaxCoins`, not a BP limit. This is a source-level mismatch requiring a Gen 5 max-BP behavior test.
5. **P0-MAUI-IO-01, unverified export/provider:** [`pktabs/PKTab.xaml.cs`](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/pktabs/PKTab.xaml.cs) uses `File.ReadAllBytes(pkfile.FullPath)` after the picker; [`AppShell.xaml.cs`](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/AppShell.xaml.cs) writes `sav.Write(flags)` through `FileSaver` with no visible same-method readback or backup. Test content URIs and read-only cloud providers; use streams rather than assuming a physical path.
6. **P0-FORGE-IO-01, not transactional:** [`AndroidSafFileAccess.cs`](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs) uses `OpenFileDescriptor(uri, "rwt")` to truncate/write an existing URI, even though its interface method is named `WriteAtomicallyAsync`. [`SafeSaveWriter.cs`](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SafeSaveWriter.cs) backs up and validates but does not reread the current provider document immediately before that write or read back its output. The `scope.Unrestricted` recovery path bypasses layout-risk checks; it is not a substitute for exact identity and safe publication.

### Minimal test protocol (not yet executed)

1. Record exact input provenance, permitted use, immutable input SHA-256 and engine/package SHA; keep real saves outside the public repository.
2. Open with a **fresh** Core process and compare trainer, slot counts, species, nickname, level, eggs, flags, per-game structures and independent checksums against the same-version desktop baseline.
3. For write tests, **only** on independently authenticated profiles, stage output in private storage; verify untouched regions and all expected changes; create a new output document; reopen and hash it; preserve source and independently test restore.
4. Run each case against local, Downloads, cloud and deliberately failing Android document providers. Capture provider capabilities, not presumed atomicity. Revoke access mid-operation and simulate stale bytes and short writes.
5. Record per-row statuses as `source-inspected`, `unit-passed`, `desktop-compared`, `device-passed`, `write-certified`, or `blocked`. These states are **not interchangeable**.

## Architecture / licence disposition

Use **official pinned PKHeX.Core + independent Android-first UI + provider-stream boundary** provisionally. Source evidence favors separating read-only projection from write authorization; neither mobile candidate has shown a complete independently validated publication path. PKForge provides useful SAF and safety *reference* patterns but direct overwrite is not atomic; MAUI has useful editor coverage but binary dependencies, absent matched test projects in its pinned tree, and visible control-flow defects. A final UI choice remains blocked on reproducible builds, device testing, per-game parity and maintenance costs.

**Do not import** PKForge's `Resources/BadApple/*` ([project bundle](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/PKForge.App.csproj)), third-party game imagery, NC-licensed fonts, MAUI's bundled sprite collections, or its prebuilt AutoMod/Injection DLLs without independent rights/source review. Source GPL compatibility is not an asset licence. No proprietary ROM, private save, console key or signing material belongs in the public repo.

**Environment limitation:** the audit runtime has no `dotnet` executable; no upstream .NET build, Android workload, emulator, or physical-provider test was executed. Do not mark Milestone 0 complete on source inspection alone. The implementation watchdog owns code/tests; audit findings are actionable tickets, not unauthorized code edits.
