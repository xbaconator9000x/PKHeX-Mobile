## P0: save and bank data-loss boundaries

**P0-IO-01 — save-provider overwrite is not an atomic transaction.** PKForge [SafeSaveWriter](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SafeSaveWriter.cs) validates candidate bytes and creates a backup, but calls WriteAtomicallyAsync without a fresh read of the provider document immediately before publication or a post-write readback. The [Android implementation](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs) opens the **existing** URI in rwt (truncate/write) mode and flushes; this is not a rename-and-swap operation and may leave a partial document after interruption. The [four writer tests](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/tests/PKForge.Domain.Tests/SafeSaveWriterTests.cs) use a fake file access whose ReadAsync throws NotImplementedException, so they cannot prove stale-source rejection, real provider durability, or readback. **Implementer:** default to new-document Save As; test changed-source refusal, interrupted/short write, readback and restore before any overwrite feature.

**P0-IO-02 — folder archive export can overwrite previously good files before its manifest is updated.** [AndroidFolderFileAccess.WriteFileAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidFolderFileAccess.cs) resolves an existing exact-name document or creates one, then opens it with wt and writes directly. [BankArchive.ExportAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/BankArchive.cs) exports entity files one by one and writes manifest.json last. If a provider fails or the process stops partway through, an old manifest may coexist with new/partial entity bytes; the source path has no readback or staged publication. **Implementer:** never call this transactional; use a new export folder or versioned immutable filenames and a verified manifest published only after successful reads, with explicit incomplete-export handling.

**P0-BANK-01 — replacement of an existing bank entity is destructive before index commit.** [FileBankService.Replace](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/FileBankService.cs) writes DataPath(id) directly **before** entering Commit, which only restores the in-memory index on failure. If SaveIndex fails, or the process crashes during WriteAllBytes, the previous entity bytes are not restored even if the index metadata remains old. The existing [index-write-failure test](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/tests/PKForge.Domain.Tests/FileBankServiceTests.cs) exercises Add/Move/RemoveMany, not Replace failure. **Implementer:** stage immutable entity bytes, validate/hash them, then commit a versioned index reference; retain old bytes until verified commit and recovery. Add a deterministic failing-index Replace regression and crash-restart test.

**P0-IO-03 — a backup receipt is not proof of durable, independently recoverable original bytes.** [FileBackupService.CreateAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/FileBackupService.cs) writes .bin followed by a JSON sidecar, prunes older versions and returns a receipt; it does **not** read back/hash the newly written pair before the caller overwrites a source, and the method does not show a storage flush-to-disk durability barrier. [ReadAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/FileBackupService.cs) verifies SHA-256 on restore, which is a useful protection, but happens later. [Backup tests](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/tests/PKForge.Domain.Tests/FileBackupServiceTests.cs) cover successful roundtrip, corrupt bytes, retention and metadata, not full-disk/cancel/partial-sidecar recovery. **Implementer:** require a verified, restorable backup before publishing any overwrite; inject disk-full and sidecar-write failures; never prune the only verified recovery point.

## P1: identity, containers, provider behavior and interoperability

**P1-IO-04 — game choice is a routing hint, not independent identity.** [SaveSessionService.OpenAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/SaveSessionService.cs) reads a URI and chooses a format using a persisted user-selected GameChoiceId; [SaveEngine.OpenSession](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Engine/SaveEngine.cs) does check several known signatures against the requested route, which is positive defensive work. But the Standard route is selected when those *known* signatures are absent; that cannot exclude an unknown hack sharing a retail envelope. MarkWritten updates an in-memory baseline from the supplied bytes, not a verified provider readback. **Implementer:** retain source-document ID, fingerprint, envelope kind and independently authenticated game/profile revision as distinct concepts; never let a user label authorize export.

**P1-IO-05 — persisted URI permission and content identity need separate tests.** [AndroidDocumentPicker](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidDocumentPicker.cs) requests read/write/persistable grants for single-save selection; [AndroidSafFileAccess.PersistPermission](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs) persists whichever read/write flags are granted. Multi-import accepts a one-off grant if persistence fails. This is useful SAF architecture but neither a write grant nor a stable URI proves unchanged content or atomic provider behavior. **Implementer:** use least-privilege read-only picker for inspection, open streams rather than filesystem paths, handle revoked grants, renamed documents, replaced bytes and read-only cloud providers.

**P1-IO-06 — the alternative MAUI candidate has path and export verification gaps.** [PKTab import](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/pktabs/PKTab.xaml.cs) reads FilePicker.FullPath with File.ReadAllBytes rather than using the returned stream, which is not a portable contract for every content URI. [AppShell.ExportSaveClicked](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/AppShell.xaml.cs) serializes via sav.Write(flags) and passes a MemoryStream to FileSaver, reporting FileSaver success without independently reopening/checking the output or creating a backup. This is source-level absence in these methods, not a claim that all MAUI provider writes fail. **Implementer:** stream-only input, independently staged output, explicit success only after provider readback.

**P1-IO-07 — permission strategy differs materially.** PKForge [AndroidManifest](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidManifest.xml) lists ACCESS_NETWORK_STATE but not MANAGE_EXTERNAL_STORAGE. MAUI's [AndroidManifest](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/Platforms/Android/AndroidManifest.xml) declares MANAGE_EXTERNAL_STORAGE and WRITE_EXTERNAL_STORAGE; [PKTab constructor](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/pktabs/PKTab.xaml.cs) calls Permissions.RequestAsync<Permissions.StorageWrite>() without awaiting its result. **Implementer:** prefer SAF grants and no broad-storage permission for the initial app; test Android API-specific permission and Back behavior rather than copying either manifest wholesale.

**P1-CONT-01 — official Core has five distinct envelope handlers; no wrapper is a retail-format identity certificate.** [SaveUtil](https://github.com/kwsch/PKHeX/blob/7e26bc53215e4f7bc0041ca375f1042539cb81b3/PKHeX.Core/Saves/Util/SaveUtil.cs) registers RTC footer, GameCube GCI, DeSmuME .dsv, Action Replay .duc and Nintendo Switch Online SRAM handlers. [SaveFileMetadata.Finalize](https://github.com/kwsch/PKHeX/blob/7e26bc53215e4f7bc0041ca375f1042539cb81b3/PKHeX.Core/Saves/SaveFileMetadata.cs) restores stored header/footer and invokes the handler's finalizer; [NSO handler](https://github.com/kwsch/PKHeX/blob/7e26bc53215e4f7bc0041ca375f1042539cb81b3/PKHeX.Core/Saves/Util/Recognition/SaveHandlerNSO.cs) updates a save hash on finalize. Handler recognition can use size and wrapper markers; this is not independent provenance. **Implementer:** capture both outer document SHA-256 and inner payload identity, preserve/validate wrapper bytes and test no-op exactness plus intentional checksum changes with the **26.10.18** engine, not solely the newer audited head.

**P1-CONT-02 — emulator normalization requires a reversible, bounded transform.** PKForge's [RetroArch RZIP decoder](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Engine/RetroArchSaveContainer.cs) checks a 32 MiB declared output cap, chunk boundaries and Adler-32, and can repack modified data; [SramPadding](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Engine/SramPadding.cs) handles erased tails and a 16-byte RTC footer. These are source-grounded design references, not permission to port them untested. **Implementer:** test RZIP truncation, wrong checksums, oversized declarations, zero/invalid chunk lengths, exact no-op byte roundtrips, edited repacks and padded/RTC variants. Never treat an arbitrary tail as disposable metadata.

**P1-CONT-03 — current reader's compressed-input rejection is intentionally incomplete.** [SaveInputRiskAnalyzer.IsArchive](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/main/src/PKHeXMobile.Domain/SaveInputRiskAnalyzer.cs) checks ZIP/GZip magic, not RetroArch #RZIP; [ReadOnlySaveInspector](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/main/src/PKHeXMobile.ReadOnly/ReadOnlySaveInspector.cs) then attempts official Core parsing for other inputs. This is **not evidence** RZIP is successfully parsed; the current policy should explicitly classify RZIP as unsupported until bounded decode and wrapper parity tests exist. **Implementer ticket:** add negative RZIP marker tests and a clear unsupported-container reason, without enabling save export.

**P1-BANK-02 — PKForge's archive manifest is descriptive, not enforced on import.** [BankArchive.ExportAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/BankArchive.cs) records per-file SHA-256 in manifest.json; [ImportAsync](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/BankArchive.cs) enumerates loose .pk files, passes bytes to a describe delegate, and deduplicates by computed SHA, but does not read/compare manifest.json or authenticate its listed hashes. This may be deliberate loose-import behavior, not a claimed vulnerability in PKM parsing. **Implementer:** define a separate *verified interchange* mode for future PokéBacon integration: schema version, file length, SHA, expected game/context, conflict and missing-file checks; loose import stays untrusted and explicitly labeled.

**P1-BANK-03 — an index backup is not an entity-content backup.** [FileBankService.SaveIndex](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/FileBankService.cs) writes a temporary JSON index, copies the previous index to .bak and replaces it; [LoadIndex](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/FileBankService.cs) tries index then backup, refusing writes if both unreadable. This is a useful fail-closed index pattern, but neither index version proves that its referenced .bin files remain unchanged. **Implementer:** content-address or version entity bytes, verify each referenced SHA on open and test stale index versus newer entity bytes.

**P1-PIN-02 — three different Core baselines cannot be called desktop parity.** [MAUI project](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/PKHeX.MAUI.csproj) pins 26.7.7; our [Core pin](https://github.com/xbaconator9000x/PKHeX-Mobile/blob/main/src/PKHeXMobile.ReadOnly/CORE_PIN.md) is 26.10.18; the inspected official source head is 7e26bc53215e4f7bc0041ca375f1042539cb81b3. Each result must state its actual package/source SHA and toolchain; do not compare a mobile value to a different Core release and call a mismatch an Android bug.

**P1-LIC-02 — code licences do not grant artwork/binary redistribution rights.** PKForge [app project](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/PKForge.App.csproj) includes external sprite, artwork, font, game-logo and other asset globs; [MAUI project](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/PKHeX.MAUI.csproj) includes prebuilt AutoMod/Injection DLL references and many resource entries. Preserve GPLv3-compatible source obligations for any code used, but separately verify each artwork/font/DLL provenance, permitted redistribution and corresponding source before importing it. No assets or code from either candidate were imported by this audit.

## Architecture disposition and actionable handoff

**Keep** official pinned PKHeX.Core behind a read-only projection boundary and a separate future write-authorisation service. **Borrow concepts, not implementations**, from PKForge: bounded wrapper parsing, backup metadata, versioned bank index, and SAF streams. **Do not borrow** its direct-overwrite semantics or MAUI's filesystem-path assumption. The initial Android picker should be read-only, path-free and least privilege; every write profile remains locked.

The [companion executable test specification](PARITY_IO_BANK_GATES_2026-10-28.md) turns these findings into 24 fixture/failure scenarios with clear owners. All remain open unless independently executed. The audit runtime lacks dotnet/Android workloads and has not run an upstream build, real save, device, provider or recovery test. **Milestone 0 remains open** pending source-pinned builds, full editor inventory, asset-rights clearance and an evidence-backed Android UI decision.
