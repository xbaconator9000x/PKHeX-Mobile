**Purpose:** unblock an Android PKHeX editor by reusing existing ports rather than reimplementing them. **Evidence level:** pinned source inspection and repository CI metadata only; no local build, device run, copied source, runtime compatibility proof, or write certification was performed in this audit. The 30-productive-hour target is aspirational, **not** a desktop-parity estimate.

## Decision

**Prefer adapting PKForge's already functional MAUI Android application as the product shell**, subject to a fast reproducible build, provenance, asset audit and fork compatibility spike. **Keep our verified domain/readback/scope safety tests as independent acceptance gates.** Use official PKHeX.Core as the long-term engine of record, but **do not blindly replace PKForge's forked Core**: first compare its exact submodule commit, public API surface and ROM-hack patches against official `26.10.18`. **Cherry-pick only proven missing MAUI editors** rather than trying to combine two entire UI frameworks. If PKForge cannot build reproducibly or the fork cannot be reconciled in the time budget, fall back to the existing native Android viewer plus small portable services; do not silently ship a fork whose save semantics are unknown.

**Crucial caveat:** PKForge's [`AndroidSafFileAccess.WriteAtomicallyAsync`](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidSafFileAccess.cs) is **not atomic across Android document providers**. It opens the original URI with `rwt` (truncate/write), writes and flushes directly; its comment itself acknowledges SAF has no portable rename-and-swap primitive. A backup made beforehand does **not** prevent interrupted or partially persisted in-place writes. Do not import that method as a safety guarantee. Start with **Save As to a distinct destination**, validate an independently reopened output and leave the original untouched; keep in-place replacement disabled pending provider-specific crash/recovery certification.

## Fastest critical path (dependency order, not fabricated completion)

1. **First spike:** build pinned PKForge Android and tests, capture exact gitlink/dependency graph, compare with our official Core `26.10.18`. Choose PKForge shell **only if** build is reproducible and fork differences are manageable; otherwise reuse its portable domain/UI patterns in current native app. No asset import before rights review.
2. **One complete editor flow:** open a synthetic supported retail save via SAF; render party/boxes; edit one Pokémon on a detached copy; show official-Core legality before/after. Cancel must not modify original.
3. **Safe Save As:** create a **new** destination URI; independent reopen verifies byte-exact output, expected save type/checksums and approved slot diff; source URI and hash unchanged; fail closed on identity/race/provider error. No in-place `rwt` writes.
4. **Expand formats, not screens first:** repeat exact desktop/Core fixture gates for claimed formats; add additional editor tabs only after the transaction path is proven. Unknown ROM-hack saves remain read-only.
5. **Release gate:** CI, clean Android build, device/provider matrix, crash/cancel recovery, rights manifest and signed artifact provenance. Only advertise features that pass.

**Immediate implementation ticket:** “PKForge-based Android editor spike with official-Core compatibility and Save As-only publishing.” Deliver a build log, pinned dependency graph, working edit-preview-cancel flow, and automated negative write tests. If spike fails, record the exact error and pivot rather than extending architecture documents.

## What this audit does not claim

No source was copied, no tests were run here, no APK was produced, no save writes were enabled, no upstream fork was proven compatible with official `26.10.18`, and no MAUI/PKForge feature was certified. See [companion execution gates](PARITY_PORT_CONSOLIDATION_GATES_2026-10-29.md).
