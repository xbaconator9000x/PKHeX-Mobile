## Two actionable P0 boundary gaps

### P0-A — independent whole-save export bypasses the read-only writer

Pinned PKForge [`BoxBrowserPage.cs` save-data menu, lines 2400–2412](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/BoxBrowserPage.cs#L2400-L2412) offers **“Export modified save”**. Its [`ExportModifiedSaveAsync`, lines 2452–2473](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/BoxBrowserPage.cs#L2452-L2473) directly calls `session.Serialize().ToArray()`, writes `<source>-modified<extension>` into `FileSystem.CacheDirectory` and invokes `Share.Default.RequestAsync`. It does **not** call `ISafeSaveWriter`, `ISaveFileAccess.WriteAtomicallyAsync`, the detached provider-bound nickname preview, a scoped diff validator or an independently reopened Save As destination.

The current adaptations [disable the editor's “Save changes” button](../scripts/pkforge_detached_preview_ui.py), [guard three BoxBrowserViewModel mutation families](../scripts/pkforge_preview_only_hardening.py) and [deny the DI and direct SAF original-document writers](../scripts/pkforge_readonly_containment.py). None of the inspected adaptation scripts replaces the `ExportModifiedSaveAsync` method or its menu route. The [neutral-assets patch](../scripts/pkforge_neutral_assets.py) changes BoxBrowserPage font/icon cache helpers, **not** this export method. Thus **source-level route remains present in the adapted checkout** unless an uninspected external mechanism blocks it. This does *not* prove a real device successfully shares a save, and does *not* imply the original source URI is overwritten; it means the “preview-only / Save As disabled” contract has an independent, unvalidated file-output path.

**Fastest fix:** for diagnostic builds, remove or disable the menu option *and* make the method fail closed before `Serialize`, `File.WriteAllBytesAsync` or `Share.Default` (direct-call defense). In future editable builds, route export through the **single** staged candidate + distinct destination + independent reopen + source fingerprint + scoped-diff transaction. Never call a share-sheet cache export “verified Save As.” Treat `.pk`, QR, Showdown, bank and event-card exports as separate explicitly classified outputs, not proof of whole-save safety.

### P0-B — inherited Android Auto Backup can copy app-private Pokémon data

Pinned PKForge [AndroidManifest.xml](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Platforms/Android/AndroidManifest.xml) declares `android:allowBackup="true"` and no `dataExtractionRules` or `fullBackupContent`. The current [neutral-assets patch](../scripts/pkforge_neutral_assets.py) changes only the manifest icon/label, not this flag. PKForge [`MauiProgram.cs` lines 41–59](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/MauiProgram.cs#L41-L59) registers persistent `AppDataDirectory/backups`, `bank`, `injected-gifts.json`, and `save-identities.json`; [`FileBackupService` lines 18–32](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/FileBackupService.cs#L18-L32) stores raw save bytes, and [`FileBankService` lines 41–51](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.Infrastructure/FileBankService.cs#L41-L51) stores Pokémon entity bytes. Diagnostic writer denial does **not** prove these app-private stores are empty or disabled, especially after an app upgrade or a bank operation.

[Android's official Auto Backup guide](https://developer.android.com/identity/data/autobackup) says enabled apps normally back up app-private data, with version-specific cloud and device-to-device behavior; for Android 12+ some OEMs can still transfer data D2D even with `allowBackup=false`. [PKHeX MAUI's pinned manifest](https://github.com/santacrab2/PKHeXMAUI/blob/a6f7cfb78e1c96155baa67660fd7ae97895e375f/Platforms/Android/AndroidManifest.xml) **also** has `allowBackup=true`, so copying its manifest is not a fix.

**Fastest fix:** fail closed on diagnostic builds: `allowBackup=false`, explicit legacy backup exclusions and Android 12+ `dataExtractionRules` covering both cloud backup and device transfer, and an independently inspected *merged* APK manifest/rules. Audit what can be written to `AppDataDirectory`; disable or isolate bank/backup persistence for preview, or move strictly necessary sensitive material to no-backup storage with a documented user-controlled export policy. A flag alone cannot erase backups already created, and neither a source XML check nor a synthetic fixture proves OEM restore behavior. Test cold install and same-package upgrade/restore with synthetic sentinel bytes; no personal saves.

### P1 — “read-only save” is not “no persistent user-data writes”

The [bank service registration](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/MauiProgram.cs#L41-L54) still points to `FileBankService` under `AppDataDirectory`. Pinned [`BankPage` export](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/BankPage.cs#L1598-L1607), [`EventGallery` export](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/EventGallery.cs#L1566-L1575) and [BoxBrowserPage `.pk` bulk export](https://github.com/sofianeelhor/PKForge/blob/2df04430e532b78c247f45b936f3068d8f824987/src/PKForge.App/Views/BoxBrowserPage.cs#L1246-L1258) create app-cache files for Android sharing. These do not directly overwrite the source URI, but need distinct preview policy, expiry/cleanup and user consent. No evidence of unintended sharing is claimed.

## Shortest safe implementation sequence

1. **One surgical temporary-checkout patch:** disable `ExportModifiedSaveAsync` at both UI and method boundaries, make bank/backup persistence explicit in diagnostic mode, and deny cloud + D2D backup in Android manifest and rules. Keep original URI write denial intact. Do not replace the PKForge UI or official Core.
2. **Execute [16 focused gates](PARITY_EXPORT_BACKUP_BOUNDARY_GATES_2026-10-29.md)** using pinned-source negative fixture first, then adapted-source and compiled APK checks. Re-run PR #75 official-Core compile, original-source fingerprint and neutral media gates. Check no diagnostic save bytes reach app-private backup, share sheet or provider writes without explicit authorization.
3. **Only then consider an internally installable rights-reviewed preview APK**, with physical Android API 30/31+ device/provider and upgrade/restore checks. Actual APK asset/transitive dependency rights and corresponding GPL source still require independent review.
4. **Later enable a single Save As path** with separately created destination URI, immutable source fingerprint, candidate checksum and scope validation, independent reopen, interruption/revoke tests and official desktop fixture oracle. Full desktop parity remains a later, separately gated project.

**Scope and safety:** audit-owned docs only. No ROMs, personal saves, secrets, binary media or license changes. No claim that the export bypass caused data loss, that Auto Backup actually ran, or that a device test was performed.
