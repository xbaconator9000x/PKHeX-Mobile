# PKHeX.Core read-only integration pin

This experimental adapter references the official NuGet package [PKHeX.Core 26.10.18](https://www.nuget.org/packages/PKHeX.Core/26.10.18) with the exact version range `[26.10.18]` (no floating updates). The matching upstream [release tag `26.10.18`](https://github.com/kwsch/PKHeX/tree/bfe89c74a3f5265805e364b79bc04ad38ebbc5ea) resolves to commit `bfe89c74a3f5265805e364b79bc04ad38ebbc5ea`. The GitHub tag identity and NuGet package version have been checked; **a cryptographic package-to-commit reproducible build comparison has not been performed**.

The audit's newer reference commit `7e26bc53215e4f7bc0041ca375f1042539cb81b3` is **not** the dependency in this adapter. Changes since the package release require explicit source and fixture comparison before any dependency upgrade. No code or artwork is copied from the mobile forks.

## Current capability boundary

- A bounded stream reader and immutable SHA-256 snapshot support non-seekable document-provider input. A second read detects changed bytes.
- `ReadOnlySaveInspector.TryInspect` calls the official Core save detector on a private copy and projects trainer, party and occupied box slots **only when Core recognizes the save, reports valid checksums, and layout caps are met**.
- ZIP, GZip and RetroArch `#RZIP` inputs (including truncated headers) are rejected before calling Core; compressed containers are not supported.
- A source-grounded, **negative-only** preflight rejects possible Unbound, GS Chronicles, Luminescent Platinum and CFRU-style Gen 3 checksum-window layouts before retail parsing. This screen is incomplete and never certifies a retail save. See [risk notes](../PKHeXMobile.Domain/INPUT_RISK_NOTES.md).
- `ReadOnlyDocumentService` provides path-free, two-open read-only APIs. Its identity-aware overload compares an opaque provider/document identity on both opens and refuses a same-byte identity change. Stream-only callers remain identity-unverified. Neither result grants write permission. This is not yet a tested Android picker/provider implementation.
- `src/PKHeXMobile.Verify` provides a strict offline manifest comparison tool for privately stored, independently baselined fixtures; there are **no independent real-save fixtures or certified formats in CI**.
- All projections are **provisional** and explicitly `SupportedReadOnly`, with no verified profile. There is no Save As, in-place write, serialization, checksum repair, ROM-hack recognition, or Android UI.
- Existing smoke tests include five synthetic negative cases and one **same-Core-generated Gen 1 positive**. The positive proves only that the adapter can inspect a synthetic in-memory save generated by the same Core; it is not independent validation. A passing CI build does not certify a single game format. Positive fixtures, game-specific semantic comparison against desktop PKHeX `26.10.18`, malformed-header and false-positive tests, Android SAF provider tests and independent checksum validation are required before advertising format support.
- Any plausible vanilla identification may still be a custom hack. No save may be written based solely on this adapter.

The separate `src/PKHeXMobile.Inspect` console harness exercises the same read-only service with user-consented local files and rechecks the source fingerprint. It is not the Android app.
